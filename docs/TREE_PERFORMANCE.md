# 节点树虚拟列表与性能记录

记录日期：2026-09-12。

虚拟列表已接入真实应用：展开行数达到 500 时，只挂载视口附近的行；少于 500 时仍使用相同的扁平树和状态模型，但不裁剪 DOM。行高固定 32 CSS px，上下各保留 8 行缓冲。展开状态不保存在行组件中，滚出视口不会丢失。

早期 `memo` 修复改善了选中更新，但未解决全部挂载的成本。本轮主要优化首次展开、宽树和大量筛选结果的 DOM 数量；不宣称 ADB、XML 解析或完整应用启动有同等幅度的加速。

## 复现命令

```powershell
bun run test
bun run test:tree-ui
bun run build
bun run benchmark:tree
bun run benchmark:render
```

- `benchmark:tree` 使用应用实际调用的 `shared/tree-utils.ts`，测量展平、全部命中、稀疏命中、零命中和可操作筛选。支持 `--json` 输出完整 JSON。
- `test:tree-ui` 只运行真实 DOM 行为回归，不进行耗时基准，结果保存在 `.benchmarks/tree-behavior.json`。
- `benchmark:render` 使用生产 React 构建和 Electron 的真实 DOM，比较旧组件 `LegacyTreeNode`、冻结的 memo 基线 `UiTreeNode` 与正式应用使用的 `UiTree`，结果保存在 `.benchmarks/tree-virtual.json`。两种旧组件及测试脚本不会进入正式 renderer bundle。
- 原始样本、环境信息、节点数量、保留数量、中位数和 P95 写入 `.benchmarks/`，这个目录已被忽略。

默认基准命令会准备本项目 Windows 运行时权限，随后保持 `sandbox: true`。启动问题和修复范围见 [Windows 启动修复记录](WINDOWS_STARTUP.md)。memo 阶段的 `.benchmarks/tree-render.json` 保留为历史记录，新基准不覆盖它。

历史上为隔离启动问题曾使用以下显式诊断命令，现在正常验收不再需要它：

```powershell
bun run benchmark:render --diagnostic-unsandboxed
```

该命令仅对无设备数据、无 preload、无 IPC 接口的合成基准窗口关闭沙箱，并通过 CSP 禁止外部资源加载。当前诊断输出单独写入 `tree-virtual-diagnostic.json`；历史 `tree-render-diagnostic.json` 保持不变。不能用诊断窗口替代正式应用验收，也不能把不同运行的差异归因于沙箱开关。

## 方法与限制

环境：Windows 10.0.26200 x64，AMD Ryzen 7 5800H；纯逻辑使用 Bun 1.4.2，渲染使用 Electron 44.3.0 / Chromium 152.0.7977.78 / React 19.3.0，使用软件渲染。性能采样为 100% 页面缩放；行为回归另外覆盖 125%。基准 CSP 会阻止应用 CSS 中的外部字体样式表，测量使用本地/系统字体。

树数据是确定性合成数据，节点数严格校验。均衡树每层最多四个子节点；宽树把其余节点放在根节点下。纯逻辑覆盖两种结构各 1,000、5,000、10,000、25,000 个节点。每项预热三次，采样十五次，计数操作放在筛选计时之外。

渲染覆盖四种规模的均衡树，以及 10,000 节点宽树；所有节点在逻辑上展开，虚拟版仅挂载当前窗口。挂载预热一次后采样三次，选中更新预热两次后采样九次，按场景交替三种实现的顺序。挂载/选中计时包含 `flushSync` 提交及强制布局；不包括完整属性面板、ADB、截图采集和保存对话框，不单独度量屏幕绘制。

虚拟版滚动额外预热两次、采样九次，交替跳到顶部和中间。React 的滚动事件是异步调度的，不能只在派发事件后立即读取旧 DOM。本基准用 `MutationObserver` 等待实际窗口索引更新后再强制布局，报告从派发到提交的延迟，包含调度等待；它不是纯函数 CPU 耗时。

完整 JSON 保存每个原始样本。小样本 P95 接近最大值，只用于发现波动。接近 0 ms 的无关更新受浏览器计时精度影响，不能解释为零开销。这些数据是本机诊断记录，不是跨设备性能承诺。

## 本轮虚拟列表结果

原始数据：`.benchmarks/tree-virtual.json`，生成时间 `2026-09-12T07:57:49.104Z`。中位耗时，单位 ms：

| 结构 | 节点数 | memo 基线挂载 | 虚拟版挂载 | 虚拟版选中并定位 | 虚拟版滚动到提交 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 均衡 | 1,000 | 28.7 | 1.6 | 1.5 | 1.0 |
| 均衡 | 5,000 | 200.0 | 2.0 | 1.5 | 1.0 |
| 均衡 | 10,000 | 314.0 | 2.7 | 1.6 | 1.1 |
| 均衡 | 25,000 | 970.6 | 13.8 | 1.6 | 1.1 |
| 宽树 | 10,000 | 345.7 | 2.6 | 1.2 | 0.9 |

本次挂载样本中，25,000 个逻辑节点对应 21 个 DOM 行；中间位置会多出上下缓冲行，行数随视口变化，不固定为 21。在不超过 450 CSS px 的视口内，回归断言上限为 32 行。小树不启用裁剪，最多挂载 499 行。25,000 节点虚拟版挂载 P95 为 18.1 ms；不同运行会随调度和 GC 波动，本文采用最后一次完整运行，没有选择最好成绩。

虚拟版跨首末叶节点选择还会自动滚动并替换窗口内容；旧 memo 基线只更新已挂载行的选中态、不自动滚动。因此两者选中耗时不用于证明单纯的 memo 优劣。500 行是本轮的保守切换值，已验证 499/500 边界，但未声称它对所有硬件都最优。

## memo 阶段历史结果

真实 DOM 沙箱运行（`.benchmarks/tree-render.json`），中位耗时，单位 ms：

| 结构 | 节点数 | 旧版挂载 | 修正版挂载 | 旧版选中更新 | 修正版选中更新 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 均衡 | 1,000 | 40.8 | 27.3 | 4.5 | 0.3 |
| 均衡 | 5,000 | 154.8 | 173.2 | 21.0 | 0.4 |
| 均衡 | 10,000 | 336.3 | 382.5 | 48.4 | 0.4 |
| 均衡 | 25,000 | 1,076.7 | 1,190.8 | 120.4 | 0.4 |
| 宽树 | 10,000 | 307.9 | 355.0 | 42.0 | 5.5 |

`memo` 主要改善更新，挂载收益没有一致性。宽树的根节点仍需遍历大量子元素，因此选中更新比同规模均衡树更慢。

纯逻辑结果摘录，中位耗时，单位 ms：

| 结构 | 节点数 | 展平 | 全部命中筛选 | 稀疏命中筛选 | 稀疏筛选保留节点 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 均衡 | 1,000 | 0.04 | 0.76 | 0.65 | 39 |
| 均衡 | 5,000 | 0.30 | 2.01 | 2.46 | 191 |
| 均衡 | 10,000 | 0.49 | 3.89 | 5.58 | 383 |
| 均衡 | 25,000 | 2.79 | 9.28 | 12.44 | 951 |
| 宽树 | 25,000 | 2.33 | 14.90 | 14.47 | 258 |

这轮实现把展平和筛选改为迭代遍历，查询词只规范化一次，并复用未变化节点的对象引用。界面中的筛选计数和定位器结果也进行了缓存，避免状态提示更新时重复计算。

## 正确性检查

15 项纯函数回归覆盖原有筛选/展平行为，以及可见行顺序、层级/同级序号、祖先展开的不可变性、隐藏焦点回退、筛选元数据、视口空/负/过大偏移、边界像素覆盖和最小滚动。20,000 层深树检查只覆盖工具函数，不代表 XML 解析和整个 App 支持同样深度。

旧 memo 基线的八类 DOM 检查继续保留。新增虚拟树十组检查在 100% 和 125% 页面缩放下分别通过：

1. 小树默认展开、展开不触发选中、空筛选后恢复展开状态。
2. 筛选自动展开；选中返回完整原始节点，避免复制/导出被裁剪的子树。
3. 25,000 节点全部展开、DOM 上限、滚出视口后保留折叠状态。
4. 外部选中深层节点时展开祖先并定位。
5. 视口外节点和重复同 ID 定位；不留下指向已卸载节点的 `aria-activedescendant`。
6. Home/End、方向键、Enter/空格和稳定的键盘焦点。
7. `0/1`、`0/10` 等相邻路径的单选边界。
8. 视口改为 320 px 后仍能正确定位，行高不漂移且 DOM 有上限。
9. 新快照重置状态，旧选中 ID 不存在时安全降级。
10. 499/500 行切换边界。

另外使用标签 getter 观测一次 256 节点树的选中切换：旧版读取 256 个节点标签，修正版读取 8 个。计时样本使用普通属性，未加入 getter 观测开销。

## 已实现的交互与状态规则

- `shared/visible-tree.ts` 迭代生成带父节点、深度和同级位置的行，保存完整索引；窗口计算只依赖行数、滚动位置和实际视口高度。
- `UiTree` 保存展开集合，`UiTreeRow` 只负责显示；筛选期间仍保留手动展开状态。过滤掉全部节点时不卸载整个树组件。
- App 的检查/历史快照会话作为组件 key，切换后重置展开/滚动；相同会话内普通状态提示不重置树。
- “全部展开/折叠”在筛选期间禁用，因为筛选结果需要保持祖先展开；“定位选中”会清除筛选、展开祖先并最小幅度滚动。
- 截图反查同样清除筛选并请求定位，即使再次点击同一个节点也有效。单纯手动滚动或折叠不会重新展开分支。
- 方向键上下选择相邻可见行，左右展开/折叠或进入子节点/返回父节点，Home/End 跳到首末行，Enter/空格选中当前行。
- 使用固定焦点容器及显式 `aria-level`、`aria-posinset`、`aria-setsize`、`aria-expanded`、`aria-selected`。键盘模型参考 [W3C Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)，尚未使用 NVDA 等屏幕阅读器实测，不宣称完整无障碍验收已完成。
- 视觉缩进在 12 层后封顶，以保留文本空间；真实层级仍通过 ARIA 和行标题提供。

## 后续边界

本轮没有验证不同 Android 分辨率、横屏、macOS/Linux、Windows 系统显示比例或屏幕阅读器。Electron 页面 125% 缩放测试不能代替这些验收。虚拟化也没有移除树索引/筛选的 O(N) 工作；完整 App 的差异计算、属性 JSON 和大 XML 解析仍可继续优化。

Windows 沙箱启动和真实应用的设备交互已有独立冒烟测试；此前仅检查主进程存活的记录不再作为窗口验收依据。该性能基准仍只度量树组件，不代表完整应用端到端耗时。
