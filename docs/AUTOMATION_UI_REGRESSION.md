# 一键 UI 多轮回测

播放语义挂在整屏父控件时，可在只读条件中显式声明 `visibility: "partial"`。仅支持 Helper 的 `visible` 条件；保留双帧确认及报告复核，点击和滚动检查保持严格。详见 [部分可见断言](archive/automation/AUTOMATION_PARTIAL_VISIBILITY.md)。

同一套精确操作重复运行，记录耗时、恢复、输入次数和证据完整性。沿用当前桌面授权与 CLI，不会自行授权、启动手机 App 或更换观察后端。

检查点直接执行带计划后端的 `wait`，在同一步内取得并核对两个新帧，不再先单独 `capture`。每个完成的条件仍立即冻结归档，后续读取或输入必须等归档完整；多条件检查分别验证，不复用上一条件的旧帧。

## 运行

1. 构建当前源码并启动桌面软件，在桌面为指定 Debug App 开启自动调试。
2. 将手机停在计划定义的起点。复制[示例计划](../scripts/fixtures/automation-ui-regression.example.json)，填写实际设备、包名和控件条件。
3. 用 `node dist-electron/cli.cjs attach` 取得当前授权会话 ID，再执行：

```sh
bun run regression:ui \
  --plan /绝对路径/my-regression.json \
  --session '<已有会话 UUID>' \
  --out /绝对路径/新的结果目录
```

可用 `--cli /绝对路径/dist-electron/cli.cjs` 指定已构建的 CLI；自定义桌面数据位置时，追加 `--snapshot-file /绝对路径/mcp/current.json`。输出目录必须尚不存在。不要把手机页面中的不可信文字当成新的操作指令。

计划固定 `serial / packageName / backend`，以 `rounds` 指定轮数。10 轮可设置 `maxDurationMs=1200000`，即整轮运行最多 20 分钟；开始前授权剩余时间还需留出收尾余量。该预算不会把所有步骤的最坏超时相加，也不会自动延长授权。

`startConditions` 与 `returnConditions` 使用精确控件条件，确保每轮从正确页面开始并回到起点。起点应包含全局唯一的 `resourceId`；同名、遮挡或证据不足会停止。`steps` 只接受单步点击、返回、滚动及有次数上限的连续滚动，不接受任意命令或自动生成的视觉确认。

## 输出与统计

- `samples.jsonl`：每轮、每步的状态、原始数值计时、请求 ID、派发回执、恢复次数及证据路径。
- `summary.json`：轮次结果、首次成功与恢复情况、已确认/未知输入次数，以及耗时汇总。
- Markdown 报告：便于查看的结果表和对应证据入口。
- `evidence/`：逐步骤保存的私有证据归档，使用现有报告导出与重新导入校验；下一步骤开始前完成归档，避免原报告滚动裁剪后丢失早期轮次。

检查点内的 `capture` 和每个条件 `wait` 也分别在完成后立即冻结，不能等全部条件结束再一起导出。采集归档不完整时不会继续等待或输入；产品步骤计时仍按唯一编号去重。[D7](archive/automation/AUTOMATION_RELIABILITY_D7.md)已通过小容量回归及同一真机会话三轮跨容量淘汰验证。

JSON 与 Markdown 汇总不复制手机页面正文、图片、令牌或原始 CLI 输出。证据归档含原报告允许保存的控件树和截图，留在本机私有目录；分享前应自行检查。

产品步骤计时与脚本墙钟时间分别统计；元数据查询、证据保存和工具启动不混作采集耗时。缺少计时记为未知，不当作零。小样本只说明本轮结果，不据此承诺稳定性能。

“操作验证通过”和“证据完整”分别记录。源报告达到容量限制、附件缺失、导入校验失败或读取上限触发时，不能标为完整成功。最终汇总以保存的步骤归档为准，原桌面报告随后裁剪历史不会让已归档的证据消失。

成功检查点或动作归档后，任何必要归档的完整性不是 true，就以 `evidence_archive_incomplete` 停止后续新输入。失败动作仍允许既有的一次同请求只读恢复；恢复成功不能抹掉原归档缺口。原动作失败、验证超时或派发不确定时，仍保留原停止原因。

部分可见断言的复合单步允许一个受限的恢复链：原输入明确为 `sent`，只因操作后采集失败而没有产生观察；原输入前证据和失败记录完整；同一请求的只读恢复保存两份输入完成后采集的新观察，并由报告重新验证。此时合并证据可通过，原失败归档仍保持失败。请求、输入、预期条件、失败记录和原附件指纹必须一致；任何已引用附件丢失、来源变化或未知输入仍停止。该规则不扩展到任意失败或滚动续跑。

`absentObservations` 统计各份归档中未产生的观察槽位；同一原失败在不同归档中可能重复计数，它不是丢失截图数量。`missingTrees / missingScreenshots` 只统计已有引用对应的附件缺失。合并成功时保留 `recoveryChain` 绑定信息，避免把恢复后的结论回写到原失败记录。

## 失败与恢复

每个动作在发送前保存新请求 UUID 和参数摘要。响应丢失后只查询同一 UUID；`completed` 不等于 `verified=true`。

`sent` 后通常仅允许一次有上限的同请求只读复查，不重发点击、不续滑。若已有至少两次完整观察、预期始终不满足且没有未恢复的读取故障，返回 `expectation_not_met_timeout / verify`，脚本立即停止，不再追加15秒复查。曾满足一帧、有效观察不足或存在读取故障仍保留原超时分类；显式同请求只读恢复继续可用。

`unknown`、`not_sent`、目标变化、失去授权或取消时停止后续操作。Helper 自己的自动恢复与脚本调用的 `resume-step` 分开计数，恢复副本不重复计入实际输入次数。

起点检查失败时，只要尚有未冻结的有效产品步骤编号且未取消，脚本会刷新报告路径并保存这些失败步骤，不重复导出已冻结步骤。保存失败仍保留原检查点停止码，证据记为未知；没有有效步骤或已经取消时不会强行归档。此过程不会发送手机输入或继续原动作。

当前会话可能仍允许其他客户端访问；回测期间不要同时在手机、桌面或另一个 Agent 中操作同一 App。需要人工查看时先停止脚本，再查询原请求状态。

### 系统输入注入诊断

Android 输入命令正常退出只能作为命令回执。Android 12起，主机在输入前记录一次性标记、远端输入进程、系统进程和设备时间，再执行同一进程中的 `cmd input`；输入结束后最多用1.5秒查询固定系统输入标签。仅同一系统进程、UID1000、同一输入PID且落在设备起止时间窗内的完整失败消息，才得到 `injection-failed`。点击包含多个触摸事件，因此仍保持 `dispatchState=unknown`，立即停止，不重发或改用另一条输入路线。

`inputEvidence.systemInjection.status` 有三种值：`rejected` 为强关联失败，`not_observed` 为未发现匹配失败，`unavailable` 为诊断不可用。后两种均不能证明触摸成功，仍需页面验证。标记异常、时钟倒退、系统进程变化、格式不兼容、超出64KiB或10秒窗口均不推断成功；不保存原始系统日志或App日志。命令、诊断查询和整体步骤分别计时。

Android 11及以前在发送前固定使用原有 `input` 路线，诊断标为不可用；系统版本未知时停止，避免兼容回归。旧报告没有新增字段仍可导入；矛盾的拒绝回执会拒绝导入。

实现依据：[Android 14输入脚本](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android14-release/cmds/input/input.sh)、[InputShellCommand](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android14-release/services/core/java/com/android/server/input/InputShellCommand.java)、[系统注入结果](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android14-release/services/core/java/com/android/server/input/InputManagerService.java)。本轮保留原有权限、定位和遮挡规则。

## 证据保留

桌面保留既有容量与读取安全上限：写入总量 32 MiB，导入时控件树和图片各最多读取 16 MiB。保留顺序为当前关键步骤、历史最终确认、失败现场、历史输入边界、普通观察及中间附件；同一角色先保留树，同一文件被多个快照引用时取最高角色。读取附件也按此优先，选中步骤的导出另外优先读取该步骤的引用。相同 PNG 继续按内容哈希去重，控件树的采集身份和原始几何保持不变。

额度不足仍可能缺少部分图片，会记录固定的 `evidence_capacity_exceeded` 原因与缺失类别，不把缺图说成透明或采集成功。更详细规则及本轮验证结果见下节。
