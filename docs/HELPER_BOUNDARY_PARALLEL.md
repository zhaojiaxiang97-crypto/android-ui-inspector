# Helper 目标与屏幕检查并行读取

2026-10-17，已实现并完成同机三轮对照：产品等待中位数由 10445.648 降至 10200.866 毫秒，减少 244.782 毫秒，约 2.34%。这是三轮探索样本，不能当作稳定提速比例。完整观察和前后校验均保留，命令数量没有减少。

## 改动

[device-actions.ts](../electron/automation/device-actions.ts) 在每个 Helper 读取边界，同时执行目标检查和主屏几何读取，再等待两项都结束。用于手机端短时等待的前后两侧，以及有授权会话的 Helper 完整观察前后两侧。

目标检查内部仍按 Activity → `run-as` → 焦点窗口顺序执行。每侧合流后先检查取消，再按目标错误、屏幕错误的顺序处理。任一失败都不会继续查询或返回结果；释放连接前，两项读取必须结束。没有缓存窗口、可调试状态或屏幕结果。

原有授权包、组件、ActivityRecord、焦点窗口、屏幕方向与尺寸、Helper 服务和转发归属检查均保留。ready 提示之后仍需两份全新的完整确认帧。UIAutomator、无会话的旧 Helper 路径和手机输入路径没有改变；没有增加协议、接口、依赖或权限。

## 原因

[上一轮对照](HELPER_CONDITION_WAIT_COMPARISON.md) 已将等待期间完整观察从 6 次降到 3 次，但总时长几乎没变。进一步按时间区间排除嵌套重复后发现：每轮 5 次短查询仍带来 50 次 ADB 命令，约占 2.95–3.23 秒；其中前后目标与屏幕检查仍串行执行。设备查询等待本身、8 秒测试页定时和最后两份完整确认帧也占时间。

本次只重叠独立读取，不缩短业务定时或确认帧间隔。并发阶段不能简单相加为“节省时间”，也不能把 50 次命令描述成已消除。

## 对照方法

- 同一手机 `DEVICE_SERIAL`、同一 `com.androiduiinspector.sdkfree` 测试页、相同 8000 毫秒倒计时。
- 两组使用同一新版 Helper、同一测试 APK 和同一私有诊断；只更换桌面边界读取代码。先测串行三轮，再测并行三轮。
- 每组预热一次；每轮基线采集后仅发送一次固定调试 Intent，再调用一次产品只读等待。失败立即停止，不补样或重发。
- 两组使用各自的有效授权会话：串行 `c7ea6567-442a-4d6d-ae53-3c5df5ab64cc`，并行 `2ebfe2d9-d451-4b6a-a792-fc3e4a08ebb9`。
- 每轮均核对同一进程、Activity 与焦点窗口、计数恰好加 1、false 新帧、ready 提示及其后的两份完整新帧。成功样本没有产品触摸输入，不代表此前输入注入失败已修复。

## 验证与证据

- 48 项相关测试通过，覆盖新增 14 项 barrier 并发/失败/取消用例、Helper 完整观察、等待执行、计划、动作校验和 UIAutomator 观察。新增用例同时验证等待与完整观察两条路径，确认没有后台读取尚未结束就返回或释放连接。
- 修复旧 UIAutomator 观察测试夹具遗漏 `inspectSystemInputInjection` 导出的 mock；没有更改该生产路径。
- 主工作树与原目录类型检查、完整构建通过；整合后原目录另复跑 20 项关键测试通过，不重复计入 48 项。

## 限制与结束状态

只有单设备、固定测试页、串行在先的三轮对照；两组都启用了会增加资源开销的同一私有诊断，不计算 P95，不外推复杂业务页面或无诊断时的稳定收益。这份结果属于桌面串行/并行对照，不能与旧版 Helper 表格混算为同一实验。

本轮两个测速会话均已结束。串行进程正常退出并写入 footer；并行进程菜单退出未完成，随后 SIGINT 使其以 exit 0 结束并由原 hook 封口。退出问题没有在本轮修复。软件已使用并行版本重新启动，并移除了私有诊断环境变量，保留原 Helper 配对配置。
