# D13：导航时重复读取的原因与候选验证

更新：2026-10-17。状态：调查和单轮候选验证完成；候选未通过门槛，未合入原目录。

## 结论

重复读取主要发生在窗口切换尚未稳定时：

1. 返回后，Helper 在一次采集中遇到旧窗口移除、新窗口加入，并有部分子节点无法读取，整次观察必须拒绝。
2. 打开视频后，Activity 字段可能暂时消失；随后还可能出现焦点为空、窗口尺寸展开。这几个阶段并非同一种错误。
3. 只补一种错误分类不能稳定消除整段恢复开销。已有两次额外读取预算可能在窗口就绪前用完；独立只读恢复随后成功，不代表应提高重试上限。

本轮实现并测试了一个受限候选，但真机仍需独立恢复，因此按预设门槛停止扩大，没有修改原目录生产逻辑。原目录仍运行 D11。D12 的整段 5.83% 收益、20% 目标未达成的结论不变。

## 证据

### 既有 D12 四轮候选报告

- 四次返回均出现 `helper-incomplete`，诊断含 `child_unavailable`（14–20 个）与 `window_inventory_changed`；窗口清单显示授权 App 的旧窗口移除、新窗口加入。
- 这四次被拒绝观察各消耗约 2.39–2.85 秒；其中树校验报错本身仅约 0.4–2.6 毫秒。大部分工作已经在此前完成，重试前再等 250 毫秒只是其中一小部分。
- 四次打开视频的原步骤均报“无法确认前台 App”；同请求恢复时出现焦点为空、窗口展开或系统窗口空档，最终取得完整新双帧。
- 每次输入均只发送一次。原失败及恢复分别保留。

### 新增诊断采样

在未修改生产逻辑的版本上，运行一次固定收藏流程，同时对返回和打开视频各采样最多 8 秒。共取得 73 个 Activity 查询结果。

打开视频时，观察到一次“命令退出码为零、无系统服务错误，但不存在 resumed Activity 字段”的样本；前后样本分别是主页面和视频页。这证明字段缺失可以出现在正常切换过程中，不能据采样间隔推算真实持续时间。

同一轮实际产品步骤首先遇到的却是焦点为空，说明不同读取时刻会落在不同切换阶段。本轮额外查询会影响时序，只用于诊断，不作为性能基线。

## 已试候选与边界

独立工作树 `navigation-observation-recovery` 中的候选：

- 仅当系统 Activity 输出有完整标题和主显示器段、命令与授权包的 Debug 资格检查均成功、没有 resumed 字段且没有权限或服务错误时，抛出专门的“Activity 暂不可用”错误。
- 仅在 Helper 来源已绑定、点击或返回已确认发送、且当前不是验证或滚动阶段时，允许原步骤有界重读。
- 沿用原有“两次额外读取、15 秒恢复预算及本步骤期限”。不接受失败观察，不缓存前台身份，不补发动作，最后仍需完整新双帧。
- 缺标题、缺主显示器、字段格式异常、显式 null 字段、命令失败、Debug 检查失败、其他 App、取消、输入前及独立等待均不因此获得额外放行。
