# 手机端短时条件等待

## 本次范围

在可选 Helper 后端增加只读条件等待。桌面完整观察发现条件尚未满足后，先让手机短时查询指定控件，减少等待期间重复传输完整控件树和整屏 PNG。设备提示就绪后，桌面仍重新取得两份完整观察，按原有条件检查器确认。

默认仍为 `uiautomator`。目标 App 不需要集成 SDK；没有启用 Helper 的流程沿用现有逻辑。正常观察已满足条件时，不增加设备等待请求。本次没有把点击、滑动或任意脚本放到手机执行，也没有减少关键边界的验证次数。

此前两轮 UIAutomator 真机计划中，观察占总时间 91.41%–92.05%，但这次改动只覆盖 Helper 的“条件尚未就绪”路径。不能据此宣称既有 42 秒计划已经提速，原始数据见[真机回测记录](archive/automation/AUTOMATION_PLAN_DEVICE_VALIDATION.md)。

## 执行过程

1. 桌面取得完整观察，检查设备、目标 App、窗口、屏幕与 Helper 来源。
2. 条件已满足时直接继续原有验证；尚未满足时调用认证后的 `POST /inspector/wait`。
3. 手机按精确选择器查询，每个请求最多 1 秒、8 次采样，不传图片和控件树。
4. 返回 `pending` 时，在当前步骤剩余预算内继续短时等待；返回 `ready` 时清空先前确认计数。
5. `ready` 只触发重新采集。桌面必须再取得两份新的完整树图，唯一目标、窗口、可见区域、遮挡、连续条件和时间顺序检查通过，才确认成功。

提示不计入已完成观察数，不生成控件快照，不产生操作许可。原步骤截止时间、会话取消和授权到期仍约束整个过程，短时查询不会重置预算。

## 协议与归属

请求格式位于[共享协议](../shared/helper-condition-wait.ts)。只允许版本、会话及请求编号、Helper 服务实例、目标包、精确选择器、条件、屏幕几何和短时预算。正文最多 4096 字节，服务端在分配正文前检查长度；没有坐标、脚本、动作或无限重试字段。

选择器沿用 `resourceId`、`text`、`contentDesc`、`className` 的精确 AND 匹配。条件支持 `visible`、`absent`、`enabled`、`disabled`。存在性条件只接受唯一的可见匹配；不存在条件只有在完整遍历后才可能提示就绪。空根、节点上限、读取失败和预算内未完成遍历均不能当作“不存在”。

成功响应只包含归属字段、`ready/pending`、匹配数、尝试数和单调时间。桌面逐项核对会话、请求、包、服务和屏幕，与上一份完整观察核对窗口及时间水位。后续完整观察也必须位于提示时间水位之后，不能复用提示前的帧。

配对令牌只证明当前配对，设备端收到的 `sessionId` 只用于归属标记。真正的调试授权仍由桌面会话控制，不把设备端令牌或会话字符串解释成新的用户授权。

## 失败与兼容

- 快照和条件查询共用读取锁，不把多个长任务排队；每次采样完成后释放锁，休眠不占锁。
- 每轮及节点遍历检查取消、预算、令牌和服务实例，前后检查窗口清单与屏幕几何。身份变化、并发占用和不完整读取均受控停止。
- 桌面等待与完整采集复用同一个自有转发、同一配对、同一会话寿命；关闭时取消请求并清理自己的连接，端口被替换时保留其他连接。
- 仅 HTTP 404 或严格的 `{ "success": false, "errorCode": "unsupported" }` 表示旧版本不支持。该能力结果在当前服务绑定内缓存，继续使用同一个 Helper 完整观察；鉴权错误、格式错误和身份变化不会被降级吞掉，也不切换至 UIAutomator。
- 仅条件等待改动时，原有严格能力响应和快照成功响应保持兼容。后续[Helper 输入实现](HELPER_INPUT_TRANSPORT.md)新增 `guardedInput` 能力字段，要求同步更新桌面与 Helper；不能将这里的历史兼容范围延伸到新输入版本。

设备短时查询要求 Android 13 / API 33 及以上，每次采样先清框架缓存。Android 官方将 [`AccessibilityService.clearCache()`](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#clearCache()) 标为 API 33，并用返回值表示是否成功清除。较低版本返回明确的不支持提示，继续原有完整观察。

1 秒是协作式查询预算。Android 的节点读取可能正在执行 Binder 调用，HTTP 取消无法证明该调用立即退出。因此不承诺硬实时停止；这一端点只读，取消后不发送输入，后续完整帧仍需通过校验。

## 验证记录

2026-10-17：实现已整合，相关 163 项测试通过（19 个文件，分组运行），包括以下场景：

- 协议的严格字段、UTF-8 字节限额、非法预算和提示不能混入树图或操作凭据。
- HTTP 404 / 精确不支持响应、错误响应不降级、旧提示、异源窗口、服务重启、转发归属及撤权清理。
- 条件未满足时使用手机查询，已满足和 UIAutomator 路径零额外查询，就绪后两份新观察，歧义目标仍失败。
- 离线完整计划调用生产 `DebugSession` 和步骤执行器，覆盖输入后等待及完整确认；等待失败时第二个动作保持待执行，不重发输入。
- JVM 执行生产 Java 方法：慢采样和短预算返回 `pending`，不完整遍历不作不存在证明；取消、锁竞争、节点回收及错误 UTF-8 / 截断正文。

主工作树与原目录的类型检查、桌面完整构建均通过；同步后原目录另外复跑 17 项定向测试通过（不重复计入上述 163 项）。Android 包使用 SDK 36、JDK 17 和已有离线 Gradle 缓存完成 `assembleDebug`，包大小 922868 字节，SHA256 为 `013c02e44748f306a6197f8de873f9f5e68265cbfbe33cfdde1b1f82fa25cd60`。独立审查发现的短片超时误停已修复并补回归，最终复审未发现新增问题。

新版 Helper 已通过 `adb install -r` 更新成功，原目录软件已重新启动。用户完成当前会话授权后，已完成下面的只读真机检查，未发送手机输入。

部署预检曾因桌面启动遗漏私有配对文件路径而被拒绝；Helper 更新也清空了内存配对状态。补齐启动配置、恢复原配对，并通过能力接口预检后重新授权，才开始下表采样。配置与人工授权时间未计入性能结果，令牌内容没有写入日志或文档。后续启动要沿用有效的 `ANDROID_UI_INSPECTOR_HELPER_TOKEN_FILE` 配置。

授权入口仍为「文件 → MCP → 开启自动调试… → 授权本次调试」，生命周期及来源检查见[Helper 会话](../electron/capture/helper-session.ts)。

取消测试前还做了 2 次计划起点观察，计入本轮总数。取消时完整采集请求已成功，进行中的提示 HTTP 请求记录为 `cancelled`。155.3 毫秒的回执表示已接收取消，当时返回的计划仍为 `running`；紧随的状态查询才确认 `cancelled`，没有测得计划进入终态的精确时刻。手机正在执行的 Binder 读取何时停止也未单独测量。
