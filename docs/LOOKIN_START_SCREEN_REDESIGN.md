## Lookin 实际是什么样

官网将 Lookin 定位为 UI 检查工具，并提供离线快照分享；具体开始页布局需要看源码。它先显示一个小型目标选择窗口，进入目标后才打开检查工作台。

| 部分 | 源码中的实现 |
| --- | --- |
| 窗口 | 初始 252×400，空状态调整为 256×400；居中、透明标题栏、可拖动背景。 |
| 没有目标 | 中间偏上的状态文字和进度指示，底部“看不到你的 App？”帮助入口。已在本机 Lookin 中查看这一状态。 |
| 有目标 | 每项显示真实 App 截图，下面是设备名称和 iOS 版本；普通预览 142×260，紧凑预览 120×220。 |
| 多目标 | 横向排列，项间距 10，窗口宽度随项数调整。 |
| 进入 | 第一次发现只有一个兼容 App 时可自动进入；多目标时点击选择。取层级成功后打开工作台。 |
| 更新 | 每轮发现完成后，约 1.5 秒再次发现目标；进入中有进度与防重复操作。 |

## 本次改造

- 删除大手机插画，收拢为居中的紧凑设备入口。
- 有该设备的本地截图时，展示最近保存的画面，明确标注“上次采集”和日期；没有截图时展示设备图标与“准备采集画面”。图片加载失败也回到此状态。
- 设备名称、Android 版本、连接状态与唯一主操作“采集当前画面”集中在一起。采集前提示在手机上打开目标 Debug App。
- 刷新与切换设备降为次要操作；连接帮助紧邻主流程。
- 开始窗口默认 440×640，最小 360×520；进入检查或高级工具时展开工作台，返回时恢复小窗口。工作台与开始页分别记住本次运行中用户调整的大小与位置，恢复时限制在当前屏幕可用范围内。
- 删除开始页底部工具栏。打开快照、历史、偏好设置、测试报告和自动调试保留在 macOS 系统菜单中；无系统菜单的平台使用顶部单一“菜单”入口。工作台内的工具入口保留。
- 开始页的历史快照使用独立弹窗，支持 Escape 和关闭后的焦点恢复。连接诊断收进连接帮助；只有已授权自动调试时显示停止按钮，菜单操作结果按需提示。
- 保留加载、未连接、未授权、离线、ADB 缺失、连接失败和已连接七种状态，以及长设备名称、键盘焦点和深浅主题。

## Android 侧的边界

当前开始页发现的是 ADB 设备，连接成功不代表某个可检查 App 已准备好。因此采集仍由用户明确触发，不照搬 Lookin 的单 App 自动进入。预览只读取已有本地快照，不增加手机截图请求，也不把历史画面标成实时画面。

沿用一个原生窗口，通过页面模式切换尺寸。保留用户主动进入的全屏状态，退出全屏后应用当前页面尺寸；工作台最大化状态也会恢复。显式指定窗口尺寸的视觉验证保持固定尺寸，避免影响已有基准。

## 实现与验证

主要实现：`DeviceHomeView.tsx`、`App.tsx`、`AppHeader.tsx`、`styles/home.css`、`electron/desktop/window-layout.ts` 与主进程/预加载窗口模式接口。沿用现有 imagegen 图标资源。

检查现有入口回归：七种连接状态、切换设备、偏好设置、历史快照、采集/取消、长名称及工具浮层。补查历史预览的设备匹配与明确标注，并分别查看深浅主题和窄窗口渲染。

本轮验证：39 项相关测试；1440×900、960×700、650×760 三档入口回归；原生窗口从 440×640 开始，打开历史快照恢复工作台尺寸，关闭高级弹窗恢复开始页。440×640 与 360×520 深浅主题均检查主要操作完整可见。

窗口行为验证：`scripts/window-layout-checks.cjs`。测试只用隔离的本地样本，不操作手机。
