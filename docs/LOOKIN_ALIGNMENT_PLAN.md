# Android UI Inspector 对齐 Lookin：Debug SDK 接入与分步改造方案

日期：2026-09-27  
状态：原生 View 混合采集和 Debug SDK 父层自身图已通过 Android 14 样例验证；业务 Debug App 首页也已通过混合采集。Qt/QML 叶子独立图和折叠时的按需整组图已在 ReClipMac 真机验证。跨系统、跨自绘类型的通用父层自身图仍未证明。

## 1. 本次决定

采用“目标 Android App 接入 Debug SDK，现有桌面端负责查看”的方案，模仿 LookinServer 的分工，不直接移植其 iOS 代码。

用户已接受目标 App 增加仅 Debug 生效的依赖。已建立独立测试工程，并在一款业务 Debug App 中以可选本地 AAR 接入、重建和真机验证；没有提交或推送。

**本方案替代上一版“先扩展 DDMS，必要时附加代理，最后才考虑 SDK”的优先级。** 后续以 SDK 为新增能力的主路线；现有 Debug View、QML 和 UIAutomator 通道保留，不在迁移开始时删除。

首版目标：在一个原生 View 测试 App 中完成“安全连接 → 真实控件树 → 独立画面 → 展开/折叠 → 属性查看 → 局部刷新”的闭环。

### 接入成本和能力边界

- 目标 App 必须有可修改、可重新构建的工程；已安装的 APK 不会因为是 Debug 包就自动拥有 SDK。
- 常规接入目标是增加一条 Debug 依赖后重新构建，自动初始化，不要求逐个修改布局。特殊自绘、额外窗口可能仍需专门适配。
- 不支持 Release App；不重新签名第三方 APK，不绕过系统权限或受保护内容。
- SDK 能直接访问进程内的 View 对象，但**不等于可以无条件拆出所有控件的独立像素**。先做画面分离验证，再决定正式接入范围。
- 保留 Electron、React、WebGL、现有树和属性面板。按 Ponytail 的最小改动原则，不新建桌面客户端、通用插件框架或另一套 MCP 服务。

## 2. 从 Lookin 借鉴什么

源码对照基线：Lookin 桌面端 `95e30fdc`，LookinServer `ae396132`。这是本次对照版本，不声称等于用户安装的最新版。

| 能力 | Lookin 的做法 | 安卓方案 |
| --- | --- | --- |
| 获取对象 | App 内集成 LookinServer | App 内集成我们的 Debug SDK |
| 展开/收起 | 展开用自身图，收起用整组图 | 明确区分 own/group 两类画面 |
| 定位控件 | 进程内对象 OID | 进程实例 + 弱引用对象 ID，不只靠路径或哈希 |
| 图像更新 | 按需、分批、局部刷新 | 树先展示，图片按需补齐，选中项可单独刷新 |
| 属性查看 | 类型、继承链、关系、布局等 | 先读真实 View 属性，再评估框架内部信息 |
| 属性修改 | 对目标对象调用受支持的操作 | 第二期再做白名单写回，不开放任意代码执行 |

依据：[LookinServer 接入说明](https://github.com/QMUI/LookinServer#readme)、[展开/收起图像选择](https://github.com/hughkli/Lookin/blob/95e30fdcc8151092678387c5262bce790a0d9530/LookinClient/Base/Category/LookinDisplayItem%2BLookinClient.m#L57)、[设备端自身图与整组图](https://github.com/QMUI/LookinServer/blob/ae396132ce6494477457cf450116dc760518d8ad/Src/Main/Server/Category/CALayer%2BLookinServer.m#L62)、[分批和局部更新](https://github.com/hughkli/Lookin/blob/95e30fdcc8151092678387c5262bce790a0d9530/LookinClient/Static/LKStaticAsyncUpdateManager.m#L134)。

这里只借鉴设计。UIKit/CALayer 的截图实现不能原样用于 Android；暂不复制上游代码。以后需要复制时，先核对对应文件、版本及许可证。

### 统一画面规则

1. 展开的父控件只保留自己真实绘制的背景、边框和装饰；父背景不会自动变成子控件背景。
2. 子控件只显示自己的像素。无底色的文字，背后应透明。
3. 收起的父控件显示包含子孙的整组画面，子孙不再重复绘制。
4. 自定义控件在一个 View 中画出的多个元素，不自动成为多个真实子 View。
5. 透明、未采集、失败、不支持、预算未覆盖、身份不确定分别说明；不能把空白全部解释成透明。
6. 真实 elevation/Z 与桌面为了观察而拉开的距离分开；测距不使用桌面“爆炸展开”的虚拟距离。

## 3. 当前代码如何接入

原有链路：`App.tsx → preload → main.ts → adb.ts → Debug View / QML → UiSnapshot → WebGL`。现已新增 Android SDK 样例工程和混合采集试验；原有通道仍保留。

混合试验的实际链路：桌面先照旧读取 Debug View 独立画面；若目标 Debug App 安装了 SDK，再通过受 `android.permission.DUMP` 保护的 Provider 请求真实 View 树，并从 App 私有文件读取结果。只有进程、窗口、全部节点身份、父子顺序及尺寸/位置均一致时，才采用 SDK 树和旧通道的图片。任何一项不符就保留原快照并提示。当前没有开放 socket 或网络端口，也没有接入业务 App。

后续若继续扩展，仍保留前后两端；下图是原完整方案，当前只实现了上述 Provider 试验链路：

```text
目标 Debug App：真实 View + Debug SDK
             ↕ 设备本地 socket，经 ADB 转发
Electron 主进程：SDK 客户端 → 现有 UiSnapshot / 增量事件
             ↕ 现有 preload 白名单
现有桌面端：树、属性、2D / WebGL
现有 CLI / MCP：复用采集与会话入口
```

| 位置 | 当前问题或约束 | 计划改动 |
| --- | --- | --- |
| `android/inspector-sdk/` | 已有 Debug Provider 导出真实树；进程内父自身图未通过 | 后续按已验证能力扩展 |
| `android/sample-app/` | 已有静态、大树和动态样例 | 保留作回归样例 |
| `electron/adb.ts` | 已复用 Provider 接口接入混合来源 | 后续局部刷新仍走统一设备/App 校验 |
| `shared/types.ts`、`shared/snapshot-validation.ts` | 已识别 `debug-hybrid`；尚无 SDK own/group 双图模型 | 需要时再增加可选字段，保持旧快照可读 |
| `electron/main.ts`、`electron/preload.ts`、`src/electron.d.ts` | 已返回整轮混合快照，尚无增量事件 | 局部刷新时再增加类型化事件 |
| `src/App.tsx` | 新快照替换会重置部分界面状态 | 区分新场景与补图，保持选中、折叠和相机 |
| `src/components/Layer3DPreview.tsx` | 生命周期依赖 root/src | 图片更新不反复创建 WebGL 渲染器 |
| `shared/layer-textures.ts` | 折叠主要靠桌面矩形合成 | 优先使用有效 group 图，保留有来源说明的合成回退 |

目前约 26 秒的完整采集记录来自特定 Android 14 页面，不能当成所有 App 的速度。V2 树虽已解析父子矩阵，现有输出/绘制链仍需核对完整变换；换数据来源不会自动修好这些显示问题。已实现能力仍以 [项目当前状态](PROJECT_STATUS.md) 为准。

## 4. 目标 App 的接入方式

### 4.1 最小接入

样例和 SDK 已放在同一个 Android 工程中，当前使用以下 Debug 专用依赖：

```kotlin
// sample-app/build.gradle.kts
dependencies {
    debugImplementation(project(":inspector-sdk"))
}
```

外部 App 初期使用构建出的本地 AAR，通过 Debug 专用依赖接入；稳定后再考虑发布仓库。当前没有已发布的依赖坐标，不编造版本号。

采用 Android 标准的构建变体隔离，不让 Release 依赖 SDK。自定义构建类型需要单独配置，名字叫 debug 不等于运行时可调试。参考 [构建变体](https://developer.android.com/build/build-variants) 和官方工具的 [Debug 专用依赖用法](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)。

### 4.2 初始化与生命周期

- 当前 SDK 使用 `DUMP` 权限保护、仅接受 shell UID 采集请求的 ContentProvider 自动初始化，authority 使用 applicationId 区分；没有新增 AndroidX Startup 依赖。
- 初始化先检查目标应用的 `ApplicationInfo.FLAG_DEBUGGABLE`；不满足就不创建 socket、令牌、采集线程或监听。
- 首版只初始化主进程，防止远程服务进程重复启动。初始化异常只关闭 SDK 功能，不阻断业务 App 启动。
- 用 Activity 生命周期回调记录可用 Activity；只在已授权采集时读取当前 Activity 的真实 DecorView。
- 不在启动时遍历整个 App、不自动截屏、不记录业务文本；未连接时不轮询或持续渲染。
- Activity 销毁、App 退到后台、桌面断开后停止相关采集任务，释放位图和对象引用。后台状态不接受新的画面读取。
- 首版不假装能通过 Activity 回调自动发现所有 Dialog、Popup 或其他进程的窗口；这部分后续单独做。

生命周期来源：[ActivityLifecycleCallbacks](https://developer.android.com/reference/android/app/Application.ActivityLifecycleCallbacks)。运行时调试标记：[ApplicationInfo](https://developer.android.com/reference/android/content/pm/ApplicationInfo#FLAG_DEBUGGABLE)。

## 5. 连接协议和安全边界

### 5.1 连接方式

原计划优先用 Android `LocalServerSocket`，通过 ADB 转发到桌面本机端口；本轮混合试验没有实施这一协议，而是复用 Android Provider + `content call`。后续只有 Provider 方式不能满足局部刷新/吞吐时才考虑 socket；不新增对局域网开放的 HTTP/WebSocket 服务。

这是设计选择，不代表仅凭“本地 socket”就安全。Android 支持抽象命名空间 socket，ADB 支持 `localabstract` 转发；还必须自己实现会话鉴权和输入限制。参考 [LocalServerSocket](https://developer.android.com/reference/android/net/LocalServerSocket)、[ADB 转发说明](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)。

连接顺序：

1. 桌面沿用现有设备、前台包名和 `run-as` 检查，确认用户正在检查的目标。
2. SDK 每次进程启动生成随机进程实例标识、随机端点名和 256 位会话令牌；端点描述仅写入 App 私有且不参与备份的目录。
3. 桌面通过已验证目标的 `run-as` 读取描述，创建自己拥有的临时 ADB 转发，并验证本机监听范围。
4. 握手核对令牌、包名、进程实例、协议版本及能力；认证前只允许握手，不返回控件树或图片。
5. 仅支持单个已认证客户端。握手超时和失败连接有数量限制，不允许一个未认证连接一直占住服务。
6. 退出、取消或错误时关闭本次任务和客户端连接，只移除本会话创建的转发，不使用全局“移除所有转发”；SDK 的监听入口按 App 生命周期保留或恢复，以便重新连接。

令牌不能进入日志、快照、MCP 输出或 Git；进程重启后旧令牌失效。桌面端描述路径、包名、socket 名和尺寸都要校验，不能把设备返回值直接拼进 shell。App 侧和桌面侧都验证请求，不信任单方校验。

### 5.2 首版协议只做只读

建议的最小请求：`hello`、`getHierarchy`、`getNode`、`getImage(own|group)`、`cancel`。局部刷新复用这些请求，不先设计一整套订阅框架。

- 使用长度前缀 + JSON 元数据，PNG 单独二进制载荷；使用 Android 自带 JSON 和 Node 现有能力，不引入 Protobuf/gRPC。
- 消息携带请求 ID、进程实例、窗口 ID、树版本和更新序号。图片另外标注对象 ID、own/group、内容版本和采集时间。
- P1 固定协议 v1；不兼容版本直接说明，未知命令拒绝，不能悄悄退回不安全协议。
- 接收前检查长度，图片解码前检查尺寸；限制字符串、节点数量、深度、累计字节及待处理队列，不能先分配任意大内存。
- 初始单图像素上限沿用 400 万像素；超出时明确拒绝或经用户选择降采样并标注比例，不静默裁切。
- 控制帧上限、总会话预算、超时等在 P0 实测后于 P1 固定为常量并测试；无界载荷不能进入集成阶段。
- PNG 编码和传输在后台执行；访问 View、读取属性和必要绘制在主线程分小批进行，主线程不等待网络。
- 取消能阻止后续任务并丢弃迟到结果，但不能声称可强制中断已进入的任意自定义 draw。单控件异常耗时后终止该轮，不循环重试。

SDK 严格限制的是“读取调试数据”。后续属性写回需要新的显式授权；现有 CLI/MCP 业务操作授权不能自动扩大为任意对象调用。

## 6. 数据与身份规则

保留现有 `UiNode.id` 快照路径及 `bounds` 语义，只按阶段增加必需的可选字段，不一次重做全量模型。

| 数据 | 含义和约束 |
| --- | --- |
| 来源 | 混合试验已新增 `debug-hybrid`；未来纯 SDK 来源再与 Debug View/QML/无障碍树明确区分 |
| 上下文 | 设备、包名、进程实例、窗口身份、采集轮次、树版本 |
| 对象身份 | 进程内递增 ID + 弱引用注册；不依赖可碰撞哈希或兄弟下标 |
| 几何 | 局部尺寸、局部到屏幕矩阵、显示四角、已知裁剪及可信状态 |
| 画面 | own/group 分开；来源、尺寸、局部坐标、时间、内容版本、完整性 |
| 状态 | 采集中、完整、部分、取消；每个缺图节点有原因 |

具体约束：

- 对象注册按引用身份比较，不能直接用可能被覆写的 equals/hashCode 当唯一键；不永久强引用 Activity/View，已回收对象及时移除。
- App 重启、Activity 重建、窗口切换后重新确认上下文。PID 相同也可能是另一进程实例，旧对象 ID 不复用。
- 列表复用同一个 View，不代表业务内容没变；刷新仍需比较内容与几何版本。
- 同一有效上下文内可保持选择；跨进程/历史快照只做标注置信度的语义对比，不猜测重复 ID 的对应关系。
- 初版读取一次完整树建立版本，图片逐项读取时再核对对象归属和尺寸/变换。页面发生结构变化时中止过期任务或要求重采。
- 图像与树不是原子同帧：记录真实采集时间，视频/动画明确提示时间差；不用“冻结整页数秒”制造一致性。
- 字段和验证器一起修改；旧快照缺字段仍可读，但不能伪称具备精确矩阵或设备整组图。
- 已有 50 MB 快照/共享限制、MCP 单图 6 MB 限制继续生效。新增 group 图计入预算，超限明确提示，不悄悄丢图。
- 树已完成但图片有失败时可以明确标注为部分结果；未通过目标/几何验证的进行中结果不能进入现有自动化操作链。

## 7. 最重要的技术验证：自身图与整组图

### 7.1 不可跳过的困难

`View.draw(Canvas)` 不是通用的“只画自己”接口：ViewGroup 会通过 `dispatchDraw` 画子控件。只调用 draw，或从整屏裁图，都会重新带入其他层内容。参考 [ViewGroup 绘制说明](https://developer.android.com/reference/android/view/ViewGroup#dispatchDraw(android.graphics.Canvas))。

现有外部补采使用的 `createSnapshot(..., skipChildren)` 是 Android 内部接口。它在 [AOSP Android 14 源码](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-14.0.0_r1/core/java/android/view/View.java) 中存在，但 SDK 位于 App 内不等于可以无条件调用。Android 对反射/JNI 访问非 SDK 接口也有限制，Debug 不自动免除全部限制。参考 [非 SDK 接口限制](https://developer.android.com/guide/app-compatibility/restrictions-non-sdk-interfaces)。

因此不能把“对象已经读到”当作“画面问题已经解决”。

### 7.2 P0 验证路径

1. 建立一个已知像素归属的样例：有色父容器、透明 TextView、图片、带装饰的自定义 ViewGroup、半透明兄弟、滚动/旋转子项。
2. 用公开绘制接口验证叶子 own 图和普通分支 group 图，确认硬件位图、阴影、alpha、圆角等限制。
3. 对容器 own 图单独验证现有 skipChildren 路径在 App 进程内的可用性；只做能力检测和安全失败，不修改系统隐藏 API 策略、不降低 targetSdk 绕过限制。
4. 特别检查自定义 `dispatchDraw`、foreground、overlay：跳过 children 不能同时误删属于父控件的装饰。
5. 对比参考渲染和采集结果，记录像素归属、alpha 是否已烘焙、裁剪、坐标、主线程耗时和失败原因。

默认禁止：为截图临时改业务子控件 visibility/alpha、移除子控件、替换布局或触发业务回调。此类方法可能改变真实页面，不能把 Lookin 的 CALayer 做法机械搬过来。

**通过门槛：** 在明确支持的原生 View 样例中，父自身图无子内容、透明文字无父底色、收起整组完整、采集不改业务状态。

**未通过时：** 暂停“完整独立画面 SDK”的正式集成，保留已有产品；提交失败类型和可选的定向适配范围。只读树/属性的成功不能替代该门槛。背景 Drawable/文字重建可以作为明确标注的降级方案，但不能叫真实独立截图；不默认扩大到 JVMTI、注入或修改系统策略。

### P0 真机结果（2026-09-27）

测试环境：小米 Android 14（API 34），样例 `targetSdk 34`，Debug/Release 均构建成功。样例由深蓝父 `FrameLayout` 与红色透明子 `TextView` 组成，未修改业务 App。

| 验证项 | 结果 |
| --- | --- |
| SDK 在进程内调用公开 `View.draw` | 父整组图有 3732 个红色像素；子图有 4872 个红色像素 |
| SDK 在进程内尝试 `createSnapshot(skipChildren=true)` | 失败：`NoSuchMethodException: android.view.ViewDebug$HardwareCanvasProvider.<init> []`，未取得父自身图 |
| 现有桌面 Debug View/JDWP 通道采集同一样例 | 14 个节点，约 2.4 秒；父自身图红色像素 0，子文字图 4872 个红色像素 |
| Release 隔离 | Release APK 的 DEX 无 SDK 类；Manifest 无 SDK 初始化组件 |

因此仅证明现有调试通道在此样例上可以正确分离画面；**未证明进程内 SDK 的自身截图能力**。Android 对非 SDK 接口的反射访问有限制；没有更改系统隐藏 API 策略或降低 `targetSdk`。用户随后同意试验混合方案。其他控件、设备与系统版本未由本样例覆盖。

### 混合试验结果（2026-09-27）

- SDK 按需导出样例的 13 个真实 View；桌面 Debug View 有 13 个对应节点和 1 个合成 Activity 根。全部 13 个对象身份、屏幕位置与尺寸匹配。
- 合并结果来源标记为 `debug-hybrid`，有 8 张独立画面。父容器图红色子文字像素为 0，子 TextView 图为 4872；没有把子文字复制到父图。
- Provider 仅随 Debug 依赖进入 APK，使用系统 `DUMP` 权限和 shell UID 检查；不支持的请求被拒绝。Release APK 没有 SDK 类或 Provider。
- 同一样例的 10×10 和 20×20 网格分别采得 125 节点/108 张图、435 节点/408 张图，均全树匹配，无 SDK 合并警告。435 节点同页三轮旧通道总耗时为 24.9/24.7/23.7 秒，混合通道为 16.0/26.9/25.5 秒；中位数约 24.7 与 25.5 秒。混合模式没有加速逐层取图。
- 动态样例在同一进程中点击后由 14 增至 15 节点，下一轮成功合并。刻意在旧图采完、SDK 读树前新增节点时，全树匹配拒绝合并，保留 `debug-view` 原快照和提示；再次采集恢复 `debug-hybrid`。
- 当前只验证单进程、单 Activity 的原生 View 样例；业务 App 尚未接入 SDK。SDK 树与 JDWP 图片不是原子同帧；动画/视频、复杂变换、多窗口、其他 Android 版本和更大树仍未验证。

### ReClipMac Android Debug 包核对（2026-09-27）

用户指定的 [ReClipMac](https://github.com/zhaojiaxiang97-crypto/ReClipMac) 当前 `bf3be41` 已有实验性 Android 端，但界面由 Qt/QML 绘制，`MainActivity` 继承 `QtActivity`。真机上的 `com.reclip.videodownloader.dev` 是可调试包：不重启 App 的 QML 调试采到约 1400 个 QML 对象；另一轮 1471 个节点中，118 个有样式信息、119 个有文字、**0 张独立位图**。Android 原生 View 树仅有 DecorView、QtRootLayout、QtSurface、QtEditText 等宿主节点，不包含这些 QML 控件。

因此现有 Android View SDK 加入此 APK 也只能补宿主 View 的属性，不能把 QML 子项变成独立 Android 图层；桌面当前正确保留 `debug-qml` 通道，不尝试 `debug-hybrid` 拼接。此轮没有修改、重签或重装 ReClipMac，也未安装缺少的 NDK。要解决其逐项画面，需要单独验证 Qt 进程内的 `QQuickItem` 自身/整组图获取能力，而不能把 View SDK 的成功当作 QML 能力。

后续验证：桌面已通过现有 QML Debug 连接调用 `QQuickItem.grabToImage()`，只对确认没有可视子项的文字、图片等控件取图；父项仍仅显示自身已读取的样式，避免混入子项像素。ReClipMac 真机首页一轮采到 1491 个 QML 节点、7 张独立文字 PNG 和 118 个样式，约 3.2 秒，不需要修改或重新安装业务 APK。Qt 按设备像素密度输出 PNG，不能拿 QML 逻辑尺寸直接校验像素尺寸。未取得独立图的 Qt 控件不再裁剪整屏截图冒充自身画面。此路径仍是保守的叶节点能力；带子控件的自绘父项能否安全取得自身独立像素，需要单独验证，当前不承诺通用支持。

### 7.3 通过后如何接入

- 默认全部展开时只优先获取 own 图，不给每个节点预先采两张图。
- 用户收起节点时，优先使用同版本 group 缓存；缺失时按需采集。等待期间可用已知 own 图本地合成，但标明来源和缺图。
- own 失败时不能拿 group 顶替，否则展开后父子会重复显示。
- 展开恢复 own；收起隐藏全部子孙。桌面选择/高亮不能改变设备上的控件颜色。
- 真实透明 own 不代表 group 透明；不能用“父控件不绘制”直接跳过其整组截图。
- 子项刷新使相关祖先 group 缓存失效；变换和裁剪变化也必须失效。
- 桌面隐藏了分支中的某层时，不能使用仍含该层的设备 group 图；改用尊重隐藏规则的本地合成，完整性单独标注。
- 历史快照离线回放，不因折叠就采当前手机。实时补图来自新时刻，显示实际更新时间。
- 合成 Activity/App 根没有对应 View，不能冒用对象 ID 请求设备截图。
- 首版正确还原二维矩形/变换；无法表达的前景遮挡、跨层绘制顺序和复杂效果如实降级，不声称与设备逐像素一致。

### 特殊表面

SDK 可直接拿到 SurfaceView/TextureView 对象，值得分别验证，但不承诺一次覆盖所有特殊渲染。

- TextureView 验证自身 bitmap 获取；SurfaceView 优先验证公开 PixelCopy 来源，不能改用 Window/整屏 PixelCopy 后称独立层。[PixelCopy 官方说明](https://developer.android.com/reference/android/view/PixelCopy) 提供了 SurfaceView 作为来源的接口。
- 普通 View group 不保证包含独立 Surface；若需合成，记录来源及捕获时间差。
- group 已经包含 TextureView 时不得再次叠加，避免视频双重显示。
- GLSurfaceView 可先作为一个输出表面验证，不把内部 GL 绘制指令伪造为 View 子节点。
- 受保护、未就绪或无法读取的缓冲分别提示，不绕过 DRM。
- 首版未验证的特殊层只报告能力缺失，不在同一快照中偷偷用旧 DDMS 图片拼接补洞。

## 8. 分阶段实施

P0 的纯 SDK 自身图门槛未通过。混合试验已跑通最小闭环，但不等于 P1–P5 完成；当前保留旧通道兼容。

| 阶段 | 交付 | 验收后才进入下一步 |
| --- | --- | --- |
| P0：样例与技术验证 | 最小 SDK 模块、样例 App、自身/整组图证据 | 核心画面分离可行，不改变业务状态 |
| P1：Debug 接入与连接 | 自动初始化、鉴权、ADB 客户端、有界协议 | Debug 可连接，Release 无 SDK，错误认证不泄露数据 |
| P2：真实树与属性 | 对象 ID、窗口归属、几何、白名单属性 | 节点匹配稳定，销毁/重建可识别 |
| P3：桌面准确显示 | SDK 快照、own/group 切换、完整二维几何 | 展开/折叠不串图，画面/边框/命中一致 |
| P4：渐进与局部刷新 | 树先显示、分批贴图、定点刷新、缓存失效 | 不重建整个场景，不误用过期结果 |
| P5：回归与试用 | 新旧通道、CLI/MCP、性能、AAR 接入说明 | 真机证据、Release 隔离、失败回退完整 |

### P0：先证明最关键的能力

1. 创建最小 Android 工程，只包含 SDK 与样例；优先 Java，避免给业务 App 增加 Kotlin/网络框架版本要求。
2. 首台验证目标为现有 Android 14 设备。记录并固定 Gradle/AGP/JDK、minSdk、targetSdk 和设备版本；未测系统只标待验证。
3. 先在 Debug 样例进程内执行第 7 节验证，P0 不开放外部监听端口；连接能力必须等 P1 鉴权完成。不先搭大规模协议、属性编辑器或发布系统。
4. 样例同时用于后续自动回归；真实 App 数据仅存忽略目录，仓库只保留合成和脱敏样例。
5. 先记录旧通道同机同页的树可用时间、首图/完整时间与覆盖率，并记录 SDK 原型的设备端采图耗时、主线程长任务和内存。每组至少三次；P5 再补相同起止口径的端到端对比，不把设备端绘制时间当完整采集时间。

交付为可复现结果和支持表；不是“编译通过即可继续”。需要目标业务 App 的源码接入时，由用户确认具体工程，不擅自修改其他项目。

### P1：让 SDK 只在需要时工作

落实第 4–5 节，先完成一个命令往返和取消。逐项测试：缺 SDK、Debug 不可用、错误/缺失令牌、描述文件过期、协议不兼容、端口冲突、断连、重复连接。

额外验收：

- Release 依赖树、合并 Manifest 和 APK/AAB 中均没有 SDK 类、初始化 Provider 或其资源；不能只验证“运行时没打开”。
- 错把依赖放入普通 implementation 的负面样例中，运行时 Debug 检查仍拒绝启动服务；同时让发布检查报错。
- 错误令牌/恶意长度不会暴露树、崩溃 App 或导致无界分配；一个慢客户端不能堵住主线程。
- 退出后无本工具遗留的转发、采集队列或 Activity 强引用；进程自然存活不等于泄漏。

### P2：真实对象与属性

先支持当前前台 Activity 的单个真实窗口，遍历 View/ViewGroup，不用 Accessibility 虚拟节点替代真实绘制对象。

读取白名单：真实类名/继承链、资源 ID、文本/描述、父子关系、宽高/局部位置、矩阵、scroll、alpha、visibility、elevation、padding、LayoutParams 和可读的 margin。字体/颜色、Drawable 类型等按选中项补读，不为全树调用所有自定义 getter。

- 名称复用现有语义命名逻辑，保留真实类名与 ID；不把推测的业务名当真实类。
- 未暴露值显示未知/不适用，不填 0。布局 px、dp、sp 明确区分。
- 字段读取有错误隔离，某个自定义控件失败不取消整棵树。
- 父子矩阵包含窗口偏移、滚动、pivot、平移、缩放和二维旋转，各应用一次。
- 无法确定的旋转 X/Y、不可逆矩阵和复杂裁剪标明限制，不制造可点击坐标。

验收：插入/删除兄弟、重复 resource-id、列表复用、Activity 重建、旋转屏幕、对象回收；旧对象请求被拒绝，正常刷新保持选中。

### P3：复用现有桌面，修正完整显示链

新增 `debug-sdk` 适配，将第 6–7 节语义接入现有类型和画面选择，不把 SDK 数据先转成缺信息的旧 DDMS 文本。

1. own/group 请求通过主进程和 preload 白名单，renderer 不直接访问设备、令牌或 socket。
2. 用局部矩形四角乘矩阵得到显示面片；WebGL 纹理、白边、选中/悬停框、2D 框和命中共用同一几何。
3. 本地 group 回退也使用相同变换/裁剪，不再把旋转图拉进轴对齐矩形。
4. 区分视觉内容范围与真实控件 bounds；进度条画面小不能直接缩小其实际点击/布局尺寸。
5. 保留现有重叠错层、全展开、相机居中、隐藏、聚焦、双击展开和测距，不重做整套交互。
6. 属性面板显示图像来源、完整性和失败原因；新能力缺失时有明确解释。

共同检查：`shared/screen-coordinates.ts`、`shared/layer-layout.ts`、`shared/layer-textures.ts`、`shared/node-metrics.ts`、`src/components/Layer3DPreview.tsx`、`src/components/ScreenshotPreview.tsx`。

验收：父背景/子文字隔离、半透明不重复变暗、纹理不双重镜像、0.5/2 倍缩放、负缩放、30°/90°旋转、非中心 pivot、两级滚动/变换与裁剪开关。合成样例的角点、边框和命中误差目标不超过 1 CSS px。100%/125%/150% 页面缩放与展开→收起→再展开均回归。

### P4：渐进显示与局部刷新

现有 Debug View 通道的初始化耗时不必等 SDK 的 P0–P3 完成才处理；独立的基线、先行优化与验收见第 13 节。

- 树通过上下文校验后先展示并默认全部展开；画面按选中/可见优先级小批返回。先允许选择、搜索、折叠和旋转。
- 图片更新带版本和序号，拒绝重复、乱序、取消后及旧轮次补丁；后续补图不能重置搜索、选中、折叠、相机。
- 将 WebGL 场景生命周期与单张图片变化分开；只换受影响纹理，释放旧纹理。纯图片更新不重排整棵树。
- 首版一个有界采集队列，不与旧 JDWP 会话同时操作同一 App；不并行启动多套采集器。
- 队列按内存/耗时反压，预算结束后报告未完成项，用户可继续补采；不能无界重试来追求“全部有图”。
- 右键增加“刷新此控件”“刷新此分支”。初版允许重读整棵树验证身份，但只重采需要的图片，不提前承诺真正增量树协议。
- 局部刷新后更新相关内容版本并使祖先 group 失效；已保存或共享的快照保持不可变，再共享生成新 snapshotId。
- App 切后台、窗口变化或对象消失时中止局部更新，提示重新采集；不自动重启业务 App。

验收：故意拖慢图片，树仍先可用；已校验结果到达桌面后以 500ms 内可见为同机体验目标，不混同总采集耗时。连续三轮、取消后重采、切 App、断连、快速重复采集、同时旋转/补图均有证据；纹理和位图内存不随轮次持续增长。

### P5：收口为可试用功能

- 产出本地 Debug AAR 和准确接入说明；未发布前不引入 Maven 发布、账号或云服务。
- 展示当前来源：“SDK 模式”或“兼容模式”。SDK 不存在时沿用旧模式并提示；鉴权失败/协议异常不静默降级，用户选择兼容模式后另起采集轮次。
- 一轮快照的树与图片来自已确认的同一来源/上下文，禁止 SDK 树加不明时刻 DDMS 图片的隐式拼接。
- QML 继续用原通道；SDK 读到 Qt 宿主 View 不等于读到了 QML 内部控件。
- CLI/MCP 复用同一采集入口并返回来源、完整性和时间信息。原有 fast UI 操作仍走现有校验，不用 SDK 对象 ID 跳过 snapshotId/屏幕校验。
- 桌面、CLI、MCP 对来源和 own/group 含义一致，原 `get_image(nodeId)` 默认含义不能悄悄改成整组图。
- 更新本计划、项目状态、README 和 CLI/MCP 说明；历史测试不冒充 SDK 验收。

## 9. 第二期：明确暂不一起做

### 多窗口

只在首版稳定后做 Activity + Dialog + Popup。先找可靠的同进程枚举方式；公开接口不足时，允许 Debug 专用显式注册，不默认反射全部系统窗口。

窗口记录独立身份、屏幕偏移、聚焦状态和可信顺序；无法确认时不拿枚举下标冒充真实 Z 序。系统输入法、权限窗口、其他 App 和其他进程不自动进入范围。窗口关闭仅使对应任务/缓存失效。

### 受限属性修改

先在桌面提供少量、明确可恢复的属性，例如文本、颜色、alpha；实施前另行确认范围。

每次写入检查对象归属与版本，记录旧值，执行后读回并刷新；撤销也要校验当前值，避免覆盖业务后续更新。结果未知不盲目重试，不提供任意方法调用、代码执行或业务对象遍历。CLI/MCP 后接入同一白名单，并要求相应授权。

### Compose、Flutter、WebView 与复杂自绘

分别做专项验证，不宣称接入 SDK 后全部解决：

- Compose 宿主 View 不等于 Composable 树；布局数据和独立图像是两项能力，需分别验证。
- WebView 宿主画面不等于 DOM 图层；Flutter/Qt 也不能通过 View 子树自然还原内部元素。
- 任意自绘内容可能需要控件专用适配；不把 Accessibility VirtualChild 伪装成真实 View。
- 不预先引入 JVMTI、字节码插桩或通用 Hook 平台；只有 P0 明确暴露无法满足的实际需求后，再单独评估成本和授权。

## 11. 回退、文档维护与第一步

| 失败情况 | 处理 |
| --- | --- |
| SDK 未接入 | 明确提示，继续现有兼容模式 |
| SDK 认证失败或上下文不符 | 拒绝数据，说明原因；切兼容模式另开轮次 |
| 容器 own 无法可靠隔离 | P0 不通过，不发布“完整独立图层”能力 |
| 单层画面不支持 | 保留边框并说明原因，不从整屏借像素 |
| group 不完整或桌面隐藏部分子层 | 使用标注来源/完整性的本地合成 |
| 几何未知 | 标限制，不猜命中点或自动点击 |
| 局部更新已过期 | 丢弃，保留上次有效数据并提示重采 |

每阶段完成后只把真实结果写入 [项目当前状态](PROJECT_STATUS.md)，未实施项保留在本方案；不另复制多份路线图。现有工作区修改全部保留，不将本次文档调整混成代码提交。

**当前有两条不同的已验证能力：**原生 View 样例上的混合采集及 Debug SDK 父层自身图，以及 ReClipMac 的 Qt/QML 对象树、样式和叶子独立图。ReClipMac 不能作为 Android View SDK 的验收对象；原生 View 业务 App 接入仍待验证。两条路线都尚未证明“任意带子项父层的自身像素”可通用获取，不能写成 LookinServer 等价实现。

## 12. 下一阶段：Qt/QML 图层画面专项（2026-09-27）

### 12.1 目标与边界

先让 ReClipMac 折叠父层时尽可能看到真实整组画面，再判定展开后能否取得**父层自己绘制的像素**。这两件事分开验收：整组图含子项，只能用于折叠；自身图不得含子项，只能用于展开。现有叶子 PNG、样式和边框继续保留。原生 View 的 `android/inspector-sdk/` 不负责遍历 QML，也不因目标 App 是 Debug 包就自动获得 Qt 内部画面。

| 视图状态 | 可用画面 | 不能做什么 |
| --- | --- | --- |
| 叶子展开 | 已采到的独立 PNG 或自身样式 | 不用整屏裁剪冒充 |
| 父层展开 | 已知自身样式；真实自身图须另行验证 | 不把含子项的截图贴在父层 |
| 父层折叠 | 已验证的整组图；否则沿用本地合成并注明缺图 | 不同时绘制已折叠的子孙 |
| 离线快照、隐藏了部分子层 | 快照内已有图或尊重隐藏规则的本地合成 | 不向当前手机补旧快照，也不用含隐藏层的整组图 |

Qt 6.8 的 [`Item.grabToImage()`](https://doc.qt.io/qt-6.8/qml-qtquick-item.html#grabToImage-method) 是异步离屏抓图并涉及 GPU 回读，没有“只抓自身、不含子项”的参数。 [`QQuickRenderControl`](https://doc.qt.io/qt-6.8/qquickrendercontrol.html) 用于应用控制的离屏场景，不等于能直接拆开现有窗口中的单个父项；Qt [场景图文档](https://doc.qt.io/qt-6.8/qtquick-visualcanvas-scenegraph.html#scene-graph-and-rendering) 也说明内置渲染器没有直接的公开访问接口。因此“进程内 Qt SDK 能通用解决父层自身图”目前只是待验证假设，不是实施前提。

### 12.2 执行顺序与每步出口

1. **固定基线和判定样例。** 记录 ReClipMac 包/提交、Qt 运行时版本、图形后端、手机系统、同一页面三轮的节点数、叶子 PNG 数、样式数、树/首图/总耗时、失败数和峰值内存。另做一个最小 Qt 页面：父项有底色与自绘装饰，子项有不透明图、透明文字，并覆盖裁剪、半透明、变换、动态更新。先用像素和屏幕观察明确“自身”和“整组”的正确结果。不能只用 ReClipMac 的复杂页面凭目测判断。
2. **先验证并按需取得整组图。** 在样例上确认对带子项 `QQuickItem` 调用现有 `grabToImage()` 会得到符合裁剪/透明规则的整组图；通过后仅在用户折叠分支时抓取，复用现有 QML Debug 连接和传图方式。初次全树采集不预抓所有父项。异步结果须核对包、进程、场景/对象身份及几何；取消、切页或对象销毁后丢弃，临时文件照旧清理。折叠后新抓的图属于**新时刻的在线预览**，须显示采集时间，不写回旧快照或暗示与原树同一帧；失败立即保留现有本地合成，不阻塞折叠。
3. **单独验证父层自身图。** 在上述样例上尝试 Qt 6.8 公开 API 的非侵入式方案；必须证明父像素仍在、子图像/文字不在、透明区域透明，且不改变目标 App 的可见性、绑定、动画或状态。不得靠临时隐藏/重挂子项、整屏扣图、私有 Qt API 或直接复用整组图“伪造自身”。把 `Rectangle`、`Canvas`/自绘项、`ShaderEffect`/视频分别记录为“通过/不支持”，不以一个控件的成功推断所有控件。
4. **按验证结果接入，而非先造通用 SDK。** 若第 3 步有可复现的安全方案，先在 ReClipMac 的 Debug 构建做最小进程内原型，再决定是否抽成可复用 Qt 适配层；需先核对与目标工程一致的 Qt Android Kit/NDK，Release 不带调试入口。若只对特定控件类型成立，只标注该类型。若公开 API 无法稳定拆分，停止通用自身图路线，保留样式/叶子图/边框和明确的“不支持”说明；不要延伸成无限制 Hook 框架。原生 View SDK 路线独立推进。
5. **最后接桌面数据与交互。** 只有整组图验证通过才给在线会话增加独立 `group` 缓存，记录来源、尺寸、时间与完整性；`own` 语义保持不变。折叠选择可用的 group，展开选择 own，隐藏分支使用本地合成；刷新子项使祖先 group 失效。补图不得重置选中、相机、搜索或折叠状态。保存新版本时可固化当时的 group，已有历史快照保持不可变、可离线回放；CLI/MCP 的 `get_image` 默认含义不悄悄改变。

### 12.3 验收与停手条件

- **画面：** 样例中展开父层不带子像素，折叠后只出现一份完整子树；透明文字无背景，半透明不重复变暗；隐藏子层后不会在 group 图里“复活”。ReClipMac 至少核对首页、动态页和一个视频/图形页，分别记录有图、透明、未暴露和失败数。
- **稳定性：** 连续三轮采集、快速折叠/展开、页面切换、对象重建和取消请求均不串图、不留下旧临时文件，不使业务 App 可见状态改变或产生 ANR。Vulkan 与可用的其他图形后端分别标记验证范围；未测不写支持。
- **性能：** 在同机同页三次中位数对比第 1 步基线；按需整组图不能拖慢初次采集或卡住折叠交互。记录每张图耗时、尺寸/实际像素、峰值内存与失败率，不靠减少采图数宣称更快。Qt 官方说明 GPU 回读可能昂贵，所以先测量再定批量和预算。
- **回归：** 复用 `tests/qml-debug.test.ts`、`tests/layer-textures.test.ts`，覆盖 own/group 选择、身份过期、隐藏分支和回退；再运行 `bun test`、`bun run build` 和真机对照。若父层自身图验证不通过，阶段也可收口：交付准确支持表与不伪造画面的折叠功能，不继续扩大改动。

### 12.4 本轮执行结果

- **判定样例：** macOS Qt 6.11.2 离屏样例 `tests/fixtures/qml-grab.qml` 的父项为红色、子项为蓝色和绿色、文字叶子透明。实测整组图含红底与蓝/绿子项；独立文字图角落透明；父项裁剪了超出边界的绿色子项。半透明父项抓图不含其**自身**透明度，但子项透明度已合成，因此 WebGL 对在线整组图只补一次父项有效透明度，对本地合成则不重复叠加。整组图**不能**冒充展开时的父项自身图。Android 真机上的 ReClipMac Debug 包也成功抓到一个含子项父层的 976×807 PNG。
- **实现：** 保持初次 QML 采集只抓叶子；仅在线、3D 视图折叠可见父分支时按需抓一张整组图。展开后立刻回到各层自身样式、独立叶子图或边框；隐藏子孙时不使用可能把它带回来的整组图。失败沿用原本地合成。请求核对包、前台窗口、进程、对象 ID/来源和边界；切换快照、展开或连续折叠时丢弃旧结果；临时图片读取后删除。界面提示整组图采集时间和“与原快照不保证同帧”。既有快照、CLI/MCP 图片语义和 ReClipMac 源码均未改动。
- **耗时：** Android 14 同一动态首页原有采集三轮为 1511/1516/1521 节点、7 张叶子 PNG、118 个样式，4.05/4.53/4.39 秒；接入后另三轮为 1571/1581/1586 节点、同样 7 张 PNG 和 118 个样式，5.15/4.97/5.64 秒。页面节点持续增长，不能据此声称初次采集更快或更慢。两次独立整组抓图约 3.52/3.99 秒、均成功；一次采样期间 16 次进程 PSS 为 682726–706109 kB（约 667–690 MiB），该数包含业务 App 自身活动，不能当成抓图的净内存开销。
- **展开父层自身图结论：** [Qt `grabToImage`](https://doc.qt.io/qt-6.8/qml-qtquick-item.html#grabToImage-method) 和 `layer.enabled` 都没有“只渲染父项、不含子项”的公开开关；[Qt 场景图文档](https://doc.qt.io/qt-6.8/qtquick-visualcanvas-scenegraph.html#scene-graph-and-rendering) 也未开放内置渲染器供逐项拆图。因此本轮停止通用自身位图路线：`Rectangle` 等已暴露的自身样式继续显示，叶子图继续显示；`Canvas`、`ShaderEffect`/视频等带子项父项的自身像素未验证为可安全取得，保持边框，不用隐藏子项或裁剪整屏伪造。
- **验证：** `bun test` 108 项通过；`bun run build` 通过；`bun run test:tree-ui` 覆盖折叠整组图、展开去除子项像素。真机首页取得整组图，未修改或重装 ReClipMac。完整桌面 smoke 已通过真实采集与 WebGL 断言，但在原有属性面板拖拽检查处超时，因此不标记全链路通过。动态页、视频页及其他图形后端未完成对照，不标记支持。

后续只做已暴露问题：在动态/视频页检验身份失效与失败回退，并在确有保存需求时让**新**快照显式固化整组图；不要扩大成未经证明的通用 Qt SDK。

## 13. 初始化采集速度专项：先处理现有 Debug View 通道（2026-09-27）

### 13.1 已测到的问题

当前 Android 14 真机前台原生 View Debug App 的**单次**完整采集耗时约 37.8 秒，读取约 1170 个节点，最终约 154 个节点有独立画面。分段耗时：读取控件树约 0.2 秒、完整属性约 1.4 秒、DDMS 批量图约 18.7 秒、JDWP 逐项补图/识别约 13.7 秒、整屏截图与前台校验约 1.0 秒。阶段计时未覆盖所有衔接开销；这只是一次实测，不是三轮中位数，也不能推断所有 App。

瓶颈主要在图像，不在树读取或 WebGL。`electron/adb.ts` 的补采候选目前包含所有满足边界条件的可见 View，**已经取得 DDMS 图片的节点也会进入 `captureViewBitmaps` 做逐个对象/类型检查**；这是为了识别不能把 DDMS 占位图当作真实图的 SurfaceView/TextureView，但普通节点也付出了检查成本。`electron/view-debug.ts` 的逐项补采还有 15 秒时限和 64 张实际补图上限。`src/App.tsx` 当前在整轮请求返回前清空快照，因此即使树很早读完，用户仍要等图片阶段结束才能操作。

Lookin 作者的[原理与性能说明](https://github.com/hughkli/Lookin/blob/Develop/Docs/Lookin%E5%8E%9F%E7%90%86%E5%8F%8A5%E4%B8%AA%E5%BC%80%E5%8F%91%E9%9A%BE%E7%82%B9.md)给出的可借鉴点是：层级先到、截图分批发送、优先处理用户正在看的层级，纯色等已知属性可先渲染；它依赖[集成在 Debug App 内的 LookinServer](https://github.com/QMUI/LookinServer)。这些是**流程参考**，不是把 iOS 截图代码移植到 Android，也不是“减少采图就算提速”。

### 13.2 实施顺序

1. **固定基线。** 同机、同 App、同页面连续采三轮，记录树可用、整屏首图、首张独立图和全部结束的时间；同时记录节点数、真实独立图数量、Surface/Texture 数、失败/超时数、传输字节、目标 App 的卡顿或 ANR。按原生 View、Qt/QML 分开报告；不拿不同页面直接对比。
2. **先减少无效逐项工作。** 统计 DDMS 已命中的普通 View 与需要特殊缓冲区的 View，优先避免对可证明不需要补图的对象重复定位。自定义 SurfaceView/TextureView 子类不能只凭类名猜测并跳过；类型不确定时保留现有检查。维持身份匹配和 own 图语义，不用整屏裁剪或父图补洞。改前后比较覆盖率与图片内容，而不只比较耗时。
3. **把首次显示从完整抓图中拆出来。** 树与前台窗口校验完成后，尽早取整屏截图并显示可操作的层级树、边框和整屏预览；DDMS 图片和特殊缓冲区图片随后补齐。DDMS 的整包响应不能假装逐张实时返回；到达桌面后再分批贴图，选中/屏幕内层优先。补图要带同一轮请求、进程、窗口、节点身份和尺寸校验；取消、切页或新一轮采集时丢弃旧图。补图不能重置选中、折叠、相机或搜索。
4. **再评估进程内 SDK 提速。** 原生 View 样例的父层自身图已通过隔离验证，现有 SDK 具备按对象试验入口；下一步先补齐桌面侧进程/窗口/对象和画面摘要校验，再做同条件三轮对照。只测 SDK 命令比完整桌面刷新快不能算产品提速；未接 SDK 的 App 保留兼容通道，Qt/QML 继续走独立路线。

3. 补真机中途取消、切 App、断连和连续重采：未完成快照不可保存，旧轮次图不能贴到新树，JDWP 转发和位图资源必须释放。失败留证并明确标为未通过，不用自动重启 App 掩盖。

**出口：** 完整 smoke 通过，或留下能稳定复现的单一失败与原因；上述切换场景无串图、无不可取消的采集。未达到出口前不宣称渐进采集全链路稳定。

### 14.2 再攻完整采集耗时

1. 固定第 13.4 节的同机同页三轮基线：1170 节点、最终约 154 张独立图、完整耗时中位数 35.75 秒。给 DDMS 批量阶段细分设备生成、传输、解码、匹配和桌面贴图时间，同时记录字节量、峰值内存、失败数及 App 是否卡顿。

3. 每个候选改动都做同页三轮对照，分别报告树可用、首张独立图、全部完成时间和真实图片数量；同时复查父子隔离、透明文字及 Surface/Texture 缓冲。以完整耗时中位数改善至少 20%（目标约 28.6 秒以内）、图片覆盖率不下降、无新增 ANR 为提速目标；未达到就如实记录或回退。

**出口：** 有可复现的耗时分解和同条件对照。若 DDMS 协议本身占主要时间且外部通道无法安全缩短，停在数据结论，转入已经通过自身图正确性验证的 SDK 试验，不靠少采图换数字。

## 15. 下一阶段：局部刷新与调试深度（2026-09-28）

目标是让用户更快看清、更新和理解**一个控件**，而不是继续堆 3D 效果。参考 Lookin 的[单图层刷新](https://lookin.work/release/Lookin-1-0-7.html)与[显示配置](https://lookin.work/faq/config-file/)；其 iOS 耗时不作为 Android 验收数字。当前 Android 14 测试页的基线是：树和整屏约 1.9 秒可用，1170 节点、154 张独立图，全量采集中位数 36.49 秒。

### 15.1 P0：先做单控件刷新，再扩到分支

### 15.2 P0：决定 Debug SDK 能提供什么

1. 沿用现有样例和仅 Debug 生效的依赖，先验证父控件**自身图**与含子项的**整组图**能否分开取得；覆盖有底色父项、透明文字、不透明子图、自绘、裁剪和动态变化。对每一类给出“通过/不支持”，不能用整屏裁剪或整组图冒充自身图。
2. 只有通过图像正确性门槛，才把 SDK 扩成按对象请求的采集入口，并比较它与现有 Debug View 通道的同机三轮耗时、图片覆盖、App 卡顿和内存。保留旧通道作为未接 SDK App 的兼容方案；Release 构建不得包含调试入口。
3. 原生 View SDK **不负责**解析 ReClipMac 的 QML 内部控件。Qt 复杂父项自身像素和 Compose/WebView 内部树继续单独列为不支持或待专项验证。

**出口：** 样例中已支持类型的 own/group 图像无父子串图；无法安全拆分的类型只显示已读样式或边框。未过此门槛，不接入业务 App，也不以 SDK 名义承诺提速。

**15.2 样例真机结果（2026-09-28，小米 Android 14 / targetSdk 34）：** 普通反射访问 `HardwareCanvasProvider` 曾返回 `NoSuchMethodException`；用户接受维护非公开接口后，Debug SDK 用 [HiddenApiBypass](https://github.com/LSPosed/AndroidHiddenApiBypass) 定向调用内部 `createSnapshot(skipChildren=true)`，没有修改设备全局隐藏 API 策略。父整组图含 3732 个红色子文字像素和 19125 个不透明绿色子项像素；父自身图两者均为 0，同时保留父控件在 `dispatchDraw` 绘制的黄色标记。绿色子项越出父边界、受父裁剪；透明文字叶子的红色像素为 4872、角落 alpha 为 0。保持同一父对象，尺寸从 731×506 变化到 816×591 后，按需取图尺寸同步，红色仍为 0，黄色标记仍在。样例覆盖的背景、子项、自绘装饰、裁剪和动态尺寸**通过**；这不等于任意自绘/Android 版本已通过。

SDK 增加 Debug 专用 `capture-own(ref)` 入口：仅 shell UID + `android.permission.DUMP` + 可调试包可调用；核对对象身份、可见状态和尺寸，返回进程实例、尺寸和 PNG 的 SHA-256，图存 App 私有目录。真机校验了摘要与文件一致、未知对象拒绝、Release APK 不含 SDK 或绕过库。SurfaceView/TextureView 明确不走该接口，仍由现有桌面专门补采。SDK 入口尚未接入桌面 UI，也未接入业务 App；桌面继续使用已验证的 JDWP 图像通道。

改动样例后，现有混合采集再次匹配 **14/14 个 View**（另有合成根），得到 9 张独立图、无警告；新增子项未破坏旧链路。

同页父控件三轮试测：SDK `capture-own` 命令加 PNG 读取为 **1.31 / 1.29 / 1.28 秒**（中位 1.29 秒）；现有桌面单层刷新为 **1.73 / 1.64 / 1.69 秒**（中位 1.69 秒）。两组校验范围不同，**不能**据此宣称产品提速。随后把进程、窗口、对象、尺寸、摘要及采集前后状态校验纳入 SDK 桌面实验，同页三轮完整耗时约 **4.49 / 4.56 / 4.50 秒**（中位 4.50 秒），现有按对象刷新约 **1.73 / 1.61 / 1.74 秒**（中位 1.73 秒）。SDK 路径更慢，故未接入桌面默认路径。混合快照现已复用原有 JDWP 单层刷新：动态尺寸/文字变化后约 1.7 秒读到新图，SurfaceView 独立缓冲约 2.0 秒；切换 App 时安全拒绝。后续只有在同等校验和覆盖率下改善 SDK 完整耗时，才考虑切换。

### 15.3 P1：补足控件语义和属性

- 命名优先使用明确的业务标识；允许 Debug App 为难辨的 `View` 提供可选调试名称。属性栏同时保留真实类名、资源 ID 和名称来源，不用推测名称覆盖原始信息。
- 对选中项按需读取可证明的继承链、`LayoutParams`/margin、几何与已暴露的交互信息；显示字段来源。没读到的约束、手势或颜色保持“未提供”，不伪造为 0 或无事件。
- 用原生 View 样例及 Qt 页面分别核对“类、关系、布局、交互”分组；Qt 没有的 Android 属性不硬套进去。

**出口：** 对一个同类控件很多的页面，能凭业务名称/ID 定位目标，且每个属性可追溯到采集来源。

**本轮进展（2026-09-28）：** Debug SDK 新增可选 `DebugNames.set(view, "业务名称")`，仅在 Debug 依赖中调用；桌面混合快照经全树匹配后才采用该名称，树和属性栏均优先显示，同时标明“Debug App 显式名称”并保留真实类名、资源 ID 和文本。SDK 也导出控件真实 `LayoutParams` 类型、宽高及仅在 `MarginLayoutParams` 存在时的四边 margin；面板标明本地 px，`-1/-2` 分别显示为 `match_parent/wrap_content`，缺失值不补 0。Android 14 真机样例得到 15 节点混合快照，两处显式名称和绿色子项的负 margin（右 -56、下 -28 px）均正确；Release APK 的 DEX/Manifest 无 SDK 类与 Provider。业务 App 未接入显式名称，不能自动给任意 `View` 猜业务名。

**继承链补验（2026-09-28）：** SDK 按实际 Java 父类生成每种 View 类一次的继承表，桌面在全树身份与几何匹配后才采用；属性栏仅对选中控件按需展开显示，旧 SDK 快照缺表时仍可读取。Android 14 真机中，自定义 `DecoratedParent → FrameLayout → ViewGroup → View` 与普通 `View` 均正确；20×20 大样例的 435 个真实 View 全部有继承链，436 个总节点、409 张独立图，无合并警告，SDK 树约 231 KB。Release APK 未包含 SDK 类。约束、手势和 Qt 对等属性仍未做；此数据不证明所有系统/厂商版本的性能。

**交互属性补验（2026-09-28）：** Debug SDK 通过公开 View 方法读取 `longClickable`、`contextClickable`、`hasOnClickListeners`、`pressed`、`activated`；混合快照验证布尔值后才写入属性栏，旧 SDK 未提供时不补成“否”。交互卡标明数据来自 SDK，并注明“没有标准 OnClickListener”不等于不能响应自绘或子项手势。真机动态样例：绿色块可长按、不可点击、无标准点击监听器；红色文字可点击、有标准点击监听器、不可长按。20×20 样例仍有 436 节点、409 张独立图、435 个真实 View 的交互标志，无合并警告。尚未读取自定义手势识别器或布局约束；Qt 属性保持原有来源，不套用 Android View 语义。

**原生布局规则补验（2026-09-28）：** SDK 仅从系统 `FrameLayout.LayoutParams` 读取 `gravity`，从 `LinearLayout.LayoutParams` 读取 `gravity` 与 `weight`；桌面验证数值后展示，常见重力位标志译成方向并保留十六进制原值，未知组合只显示原值。没有字段就不显示规则，不从屏幕位置反推。Android 14 真机：蓝色父卡重力 17（居中）、绿色子项重力 85（右下），20×20 样例中一个线性子项权重 1、未指定重力 -1；大树仍有 436 节点、409 张独立图且无合并警告。`RelativeLayout`/AndroidX `ConstraintLayout` 的锚点与约束、Qt 布局规则尚未接入。

**业务 App 首次真机验证（2026-09-28）：** 可选 SDK AAR 已接入一款业务 Debug App 并安装到 Android 14 真机。约 1150 个真实 View 的页面超过原 250 ms 主线程遍历限时；改为最多 1000 ms 后可读。旧流程在约 40 秒的独立图采集之后才取 SDK 树，动态控件的位置已变，整树匹配安全回退；现在紧贴 DDMS 层级读取时取 SDK 树，仅对同一对象允许最多 8 px 的位置漂移，身份、父子关系、尺寸和文字仍须一致。连续两轮业务首页完整采集均得到 1152 节点 `debug-hybrid`，其中第二轮 209 张独立图，约 41.6 秒。此结果验证了混合链路，没有证明比旧通道更快，也不放宽图片按身份匹配的规则；其他设备和页面待验。

### 15.4 P2：安全修改与小型显示配置

- 等 15.2 的对象身份稳定后，才考虑 Debug 专用、用户主动触发的少量属性写回；首版最多验证 `visibility`、`alpha`，写前读值、写后核验、提供撤销。历史快照保持不可变，不开放任意方法调用控制台。
- 再补可选的默认折叠类型、跳过指定图像、业务颜色别名，以及 2D 测距固定显示。复用现有树、采集和测距实现；配置必须有清晰的重置入口。

**本阶段不做：** 为追 Lookin 外观重写 WebGL、承诺所有自绘/Qt/Compose 图层有独立像素、绕过受保护内容，或把 iOS 的“3 秒快速模式”直接设为 Android 指标。实施时先完成 15.1 的单节点验证，再根据实测决定是否扩展协议；每阶段通过后才进入下一阶段。
