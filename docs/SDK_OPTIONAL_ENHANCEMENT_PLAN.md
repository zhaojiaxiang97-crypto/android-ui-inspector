# Inspector SDK 可选化改造计划

日期：2026-10-15。状态：**方案已整理，尚未实施**。本次只交付计划，不改变采集默认值、手机依赖或桌面安装版。

## 1. 目标与范围

默认让用户连接设备、打开 Debug App 后直接检查，不要求业务工程接入自研 Inspector SDK。SDK 保留为需要时开启的增强能力，暂缓继续扩展专项实验。

这里的 SDK 指 `android/inspector-sdk`，不包括桌面仍需要的 Android Platform-Tools / ADB。免接入也仍要求目标 App 可调试、设备已授权，不扩大为任意 Release App 检查。

- 默认主线：控件树、基础属性、截图、可取得的独立图，以及树选择、2D/3D、测距、历史和导出。
- 可选增强：已有 SDK 树与属性补充、部分复杂画面与组图采集、实时样式、业务主动登记的名称和结构化信息。
- 保留 SDK 源码、Debug 接入方式、协议、样例和已有测试；不删除业务工程中的依赖，不自动更新手机 App。
- 不新建通用插件框架，不同时改造 QML、Helper、UIAutomator 或 3D 排层算法。

## 3. 用户体验

在已有设置中增加“启用 SDK 增强”，默认关闭。说明：**“适用于已接入 Inspector SDK 的 Debug App，可读取更多画面和业务信息。”** 接入文档放在该设置旁，首页保持设备选择和采集入口。

| 模式 | 行为 |
| --- | --- |
| 标准模式（默认） | 不做 SDK 专属探测、不创建 SDK 会话、不发 SDK 内容请求；走已有原生采集路径 |
| SDK 增强 | 用户主动启用后才探测；按已验证的能力选择 SDK 路径；未安装或能力不足时保留基础采集，并说明实际使用的来源 |

新配置及缺少该字段的旧配置均默认标准模式；不因为目标 App 已安装 SDK、历史快照含 SDK 字段或实验环境变量而自动开启。用户显式保存过的选择才持久化。

切换规则：采集、刷新或自动调试运行期间禁用切换，并提示先结束当前操作；空闲时切换立即保存，释放闲置 SDK 会话并失效旧实时补采资格和模式绑定的请求缓存。快照中已取得的图片与信息保留，已有画面可继续查看，需要重新整页采集后才能刷新或补图。切换不自动操作手机。

增强模式缺失能力时沿用兼容回退；取消、进程或窗口身份变化等错误继续终止，不伪装成普通缺少 SDK。缺图明确标记，不裁整屏冒充独立图。

## 4. 代码边界

### 4.1 一份策略贯穿整次操作

拟增加明确的策略值 `standard | sdk-enhanced`。字段名称在实施时与现有契约统一，以下是职责约束：

1. 桌面主进程保存并校验偏好；renderer 通过既有窄接口读取和修改，采集请求不能绕过设置临时开启增强。
2. 开始整页采集或自动调试会话时固定策略，传入 [InspectionOptions](../electron/capture/types.ts) 和 [CaptureRunContext](../electron/capture/run-context.ts)。重试继承同一策略。
3. 扩展现有 `CapturePlan` 决定是否允许 SDK；通过已有注入边界调用 SDK，避免新增平行采集框架。原来的图片优先参数或环境开关不能绕过标准模式。
4. 实时会话保存采集策略与模式版本。补图、刷新、组图和样式请求复用它，并检查它仍与当前设置一致；旧快照的 SDK 标记只是数据来源，不是调用许可。
5. 对异步结果继续检查请求身份和模式版本，失效结果不能更新树、属性、图像缓存或共享快照。

策略只决定采集后端，不能替代自动调试的输入授权、目标限定、取消和数据校验。

### 4.2 必须覆盖的入口

| 入口 | 必须满足的行为 | 主要落点 |
| --- | --- | --- |
| 桌面整页采集、只读诊断 | 同一默认值；标准模式连 SDK 探测都不发起 | `inspection-service.ts`、`capture-ipc.ts`、`inspection.ts` |
| SDK 树采用、图片路由、缺图补采 | SDK 前置准入，包括 `bitmapTarget` 注入的 SDK 唤醒；原生窗口和进程校验继续执行 | `capture-plan.ts`、`debug-images.ts`、`sdk-tree-verification.ts`、`sdk-images.ts` |
| 单控件、分支、列表刷新 | 从实时会话取策略；SDK 快照与标准模式不直接混合刷新 | `refresh.ts`、`inspection-service.ts` |
| 按需组图、实时样式 | 标准模式不请求 SDK；使用已保存图或现有本地重建，明确来源；SDK 专属实时样式显示能力不可用 | `refresh.ts`、`group-image-cache.ts`、属性面板 |
| 自动调试 deep、CLI/MCP 触发采集 | 从桌面持有的调试会话继承策略，不增加绕过开关；fast 的 UIAutomator/Helper 选择保持独立 | `main.ts`、`electron/automation/` |
| CLI/MCP 只读共享 | 读取已有数据，不因含 SDK 字段而补采 | `electron/automation/` |
| CLI/MCP 连接诊断 `diagnose_connection` | 无可信桌面模式来源时按标准模式；关闭时跳过 SDK 专属声明探测，显示“增强未启用”，不当作基础检查失败；开启后 SDK 诊断仍是可选项 | [诊断执行](../electron/automation/connection-diagnostics.ts)、[诊断结果](../shared/connection-diagnostics.ts) |
| 历史、导入、导出、图片预览 | 旧 SDK 数据照常展示；离线行为不探测设备、不连接 SDK | `src/features/history/`、图片预览与导出模块 |

完整代码路径和职责导航见[开发目录](DEVELOPMENT_STRUCTURE.md)。对 `refresh.ts` 中各独立入口逐项检查，尤其不能漏掉实时样式、组图和 SDK 唤醒。

### 4.3 保留与维护方式

- 继续使用现有 SDK Provider 池；标准模式不建立会话，增强模式按需使用。取消、迟到回复、线程与端口清理沿用现有规则。
- SDK 仅通过业务 Debug 依赖接入；Release 隔离、数据格式和快照兼容保持现状。
- 保留 SDK 回归检查；暂停的是新实验和业务接入扩张，不是已有安全边界、兼容性和缺陷维护。
- 主 README 和第一次使用以免接入流程为主；Android README 作为可选增强入口，既有专项历史不复制回主文档。

P1、P2 是同一交付前的内部步骤，不发布只关闭首轮图片路由的半成品。本计划不包含桌面安装升级或业务 APK 更新。

## 6. 验收要求

| 场景 | 通过标准 |
| --- | --- |
| 新配置、旧配置缺字段 | 默认标准模式，设置与主进程一致 |
| 完全未接 SDK 的 Debug 样例 | 树/属性/截图、可用独立图、2D/3D、测距、刷新、保存重开和导出流程可用；独立图结果逐项记成功、缺失或失败 |
| App 已装 SDK，但用户关闭 | 整页及所有后续入口的 SDK 探测、会话、内容调用数均为 0；实验参数不能绕过 |
| 开启增强，App 无 SDK、旧 SDK、新 SDK | 分别验证基础回退、按能力选择和已有增强；取消及身份错误不被吞掉 |
| 自动调试及 CLI/MCP | deep 继承模式；fast 不受影响；只读共享不补采，关闭共享与停止行为仍有效 |
| 无桌面调试会话的连接诊断 | 默认标准模式，零 SDK 专属探测；基础连接成功不因未启用增强判失败 |
| 模式切换、取消、迟到结果 | 忙态不能切；空闲切换失效旧实时会话；旧结果和缓存不能污染下一模式 |
| 打开含 SDK 数据的历史快照 | 信息与图片保留；查看、导出零设备请求；SDK 专属实时操作不暗中恢复连接 |
| 复杂窗口和图片缺失 | 软件窗口、Surface/Texture、离屏、超大树按实际支持报告；不把缺图当透明，不承诺逐像素等价 |

测试优先扩展现有采集策略、会话、刷新、自动调试和历史用例，不重复创建同类测试体系。运行相关测试、类型检查与构建；原生桌面流程和无 SDK 样例真机结果单独记录，不能用模拟测试替代。

性能记录区分树就绪、首个可用画面、总耗时和实际独立图数量。使用相同样例页面比较改造前后；如对比标准/增强模式，固定两份 APK 的代码、构建环境与画面条件，只改变 SDK 接入。保留失败与缺图，不提前承诺标准模式更快。

## 7. 风险与回退

- **画面能力减少**：系统调试接口可能拿不到某些真实画面或完整属性；保留清楚的缺图说明与增强入口。
- **存在漏掉的隐式 SDK 调用**：以所有入口的零调用断言和真机调用记录验收，不只检查设置值。
- **旧快照混合刷新**：模式切换后要求重新整页采集，历史数据继续只读。
- **范围膨胀**：本轮不拆 SDK 为新仓库、不替换采集协议、不新增后端注册系统，不借机扩展设备实验。

实施遇到基础路径缺陷时，保留失败证据，推迟默认模式交付；用户仍可主动启用增强。需要代码回退时按批次撤回，不删除 SDK 实现或改写旧验收结论。
