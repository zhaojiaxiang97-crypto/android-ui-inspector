## 2026-10-21 真机取证进展与屏幕方向反例

完成一次 308 节点、每块 8 轮的原版 A → 计时版 B → 原版 A 只读预检。24/24 回执均为 `completed / not_sent`，请求 ID 和快照 ID 各 24 个不重复。但**严格对照程序拒绝此组数据**，因为各组的真实屏幕方向不一致：

| 阶段 | 屏幕和旋转 | 预检墙钟中位数 | 设备完成预检中位数 |
| --- | --- | ---: | ---: |
| A-before，原版 | 2400×1080，rotation 3 | 805.5ms | 759.5ms |
| B，分段计时版 | 1080×2400，rotation 0 | 798.5ms | 758ms |
| A-after，恢复原版 | 1080×2400，rotation 0 | 791ms | 743.5ms |

以上 24 轮只证明各次只读目标预检能在原 1000ms 内完成，**不能跨横竖屏计算探针开销或提速百分比**。拒绝原因由现有 `compareHelperProbes` 的屏幕身份校验实际返回，没有人工改写回执或放松判断。

这一组不合格原始数据仍然保留以解释为何重新取样；有效竖屏三组结果见上节。覆盖安装曾使 Helper 配对临时失效（HTTP 401），用户后续通过手机原生页面重新配对；一次连接器尝试打开本机私有令牌文件被平台安全检查拒绝，未绕过。

## 采样顺序

另一次独立的每块三轮补充对照已完成，数据保存在 A2 隔离工作树 `.benchmarks/open-source-plan/a2-aba-20261021/`，不与上文每块八轮合并统计。三组均固定 308 节点、相同屏幕，9/9 completed/readOnly/not_sent；原版前组墙钟 790、784、801ms（中位 790ms），计时版 826、792、794ms（中位 794ms），原版后组 752、815、797ms（中位 797ms）。严格比较器通过；原版漂移 +0.89%，计时版相对两组原版平均中位数差 +0.06%，设备预检差 +0.40%。样本量小且差值低于原版漂移，不能证明无扰动、提速或外推至 758 节点超时页。

补充组的 manifest.json 与 comparison.json 保留完整回执和聚合。`fixtureSha256` 在该清单采用已安装测试 APK 内所有 classes*.dex 的确定性摘要（按 ZIP 名排序，将文件名、NUL 分隔符、DEX 字节依次送入 SHA-256），不声称当前工作区源码与已安装 APK 逐字对应。最终从设备拉回测试 APK 摘要与采样前一致；Helper 已恢复原版并再次拉回核对摘要，授权已停止，ADB forward 为空，无障碍服务仍启用。后续研究以当前下一步计划为准，不重复启动已经完成的探针对照。

1. 固定同一设备、Android 版本、自有 Debug App APK、夹具源码、页面参数、目标与屏幕。每轮先建立新完整快照，再运行一次现有 `helper-target-probe.ts`。
2. 按原版 A → 计时版 B → 同一原版 A 顺序，每组保留相同轮数，至少 3 轮、最多 20 轮。保留全部成功和超时，不挑选结果。每次换包核验 APK/签名和配对，并按产品流程建立有效授权。
3. 不完整、拒绝、认证失败、页面变化或旧快照重复使用时，先调查原因，再重新采集整组。不得自动重试输入。记录冷启动、预热、后台负载和采样间隔；三组条件保持一致。
4. 结束后撤销授权，恢复备份 APK，核对摘要并清理自有转发。覆盖安装后配对失效需要按当前产品流程重新配对。

## 清单结构

顶层字段：`version: 1`、`serial`、`packageName`、`fixtureSha256`（固定夹具代码摘要，须注明源码或已安装 DEX 口径）、`sampleApkSha256`（测试 App 摘要）、`blocks`。

`blocks` 严格为三项，依次是 A-before、B、A-after。每项包含 `apkSha256`（该组 Helper APK 摘要）和 `samples`。两组 A 的摘要必须相同，B 必须不同。

每个样本保留原 `helper-target-probe.ts` 的完整 JSON 输出：`nodeCount`、`observationMs`、`probeWallMs`、`helperDeadlineMs`、`reply`；另加 `serial` 和 `capturedAt`（主机采样时间，UTC ISO 格式，如 `2026-10-21T06:00:00.000Z`）。按真实顺序排列；每轮 requestId、captureId 必须独立。不要将 Android uptime 当成跨安装的主机时间。

协议会拒绝未知字段、非只读或已派发回执。清单上限 1 MiB。原始材料保存在本机忽略目录，对外只分享聚合结果。

## 结果怎么读

- 输出三组完成/超时数量、采集和预检墙钟中位数，以及前后原版的漂移百分比。
- 候选墙钟差相对两组原版中位数的平均值计算，正值表示更慢，负值表示更快；不自动认定有收益。
- 只有全部轮次完成时，才报告设备端完整预检耗时差。存在超时就返回 `null`，因为真实完成耗时被 1000ms 截止截断；不能将超时墙钟当成完成速度。
- 相同节点数与声明摘要只是基本准入，工具无法证明页面像素、目标和系统负载相同。必须结合原始环境记录与回执复核，不把统计准入当作真机条件已经验证。
- 该工具不验收完整收藏流程；正式 D24 仍为 0/3，整段 20% 提速仍未达到。

离线对照工具开发阶段，隔离工作树和主目录各自运行同一组 6 项相关测试，均通过（不合计为 12 项不同测试）；类型检查、主目录完整构建及 `git diff --check` 通过，构建保留已有的大于 500 kB 产物块提示。测试覆盖完整样本、超时截断、APK 顺序、轮数、设备/App/屏幕/节点数不一致、旧请求/快照复用及已派发回执。实现不改生产扫描、唯一性、预取参数或 1 秒门卫。该离线开发阶段未安装 Helper 或发送手机输入；后续完整真机 A/B/A 的安装、恢复及授权证据见上文。
