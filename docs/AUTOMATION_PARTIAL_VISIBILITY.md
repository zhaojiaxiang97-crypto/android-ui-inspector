# 部分可见的只读断言

更新：2026-10-17。

## 解决的问题

播放器把“暂停视频”放在整屏父控件的无障碍描述中。顶部状态栏、底部导航栏和小浮窗只遮住部分区域，但原来的 `visible` 断言要求整个矩形无遮挡，因此拒绝确认。

新增显式选项 `visibility: "partial"`。默认行为保持不变，只允许 `state: "visible"` 使用这个选项，且要求完整的 Accessibility Helper 观察。它可以用于等待、动作后的预期和任务验收。

桌面操作计划只在 `wait` 和 `step.expect` 中支持；计划的起点、终点和 `when` 仍使用独立采集，尚未持久绑定确认对，因此明确拒绝这个选项。多轮回测脚本的起点与返回检查使用 `wait`，可以支持。

```json
{
  "selector": {
    "resourceId": "com.example:id/player",
    "className": "android.widget.FrameLayout",
    "contentDesc": "暂停视频"
  },
  "state": "visible",
  "visibility": "partial"
}
```

命令行等待对应 `wait --resource-id com.example:id/player --desc 暂停视频 --visibility partial`，同时需要本次会话参数。多轮回测计划直接在条件中声明，不额外放宽输入目标。

## 判断方式

1. 校验完整控件树、前后窗口清单、屏幕参数、焦点和 Helper 服务身份。
2. 每次观察都必须唯一匹配目标，并确认其可见标记及有效区域。
3. 从目标有效区域中扣除所有同层或更高层的其他窗口。多个窗口联合遮住全部区域时不能通过，未知窗口或几何不足也不能通过。
4. 两次新观察必须属于同一页面、窗口和服务，目标身份一致，并存在共同露出的正面积区域。
5. 成功等待保存两次确认帧的引用和附件。报告导入重新计算；缺帧、身份变化或附件无法核对时不能保留“已验证”。

矩形拆分有数量上限，超过预算返回证据不足，不截断窗口后宣称通过。`partial` 只表示存在稳定露出部分；一条细缝也符合几何定义，不表示控件内容足够清晰可读。

## 使用边界

- 点击、滚动、滚动终点以及 `absent/enabled/disabled` 仍使用原有严格规则。
- 不支持用 UIAutomator 的不完整窗口信息替代 Helper 证明。
- 只读恢复沿用原请求，不重复发送输入。
- “暂停视频”证明 App 暴露了该语义，不能单独证明视频持续播放。实际播放仍需画面变化或进度证据。
- 当前窗口证据不能证明同一窗口内部所有兄弟图层的像素遮挡，也不能定位父容器描述对应的具体文字区域。
