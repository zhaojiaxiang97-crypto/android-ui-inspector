## 本次修正

[D21](AUTOMATION_CONTROLLED_AB_D21.md) 的一次返回已确认发送，但后续读取只得到“无法确认前台 App”，无法判断是命令失败、没有前台目标，还是格式不识别。

现在 `checkedDebugTarget` 统一产生固定类型的错误，由现有步骤报告保存以下代码：

| 代码 | 含义 |
| --- | --- |
| `foreground-query-failed` | 活动查询命令抛错、非正常退出，或系统明确返回权限、服务、dump 超时错误 |
| `foreground-missing-field` | 响应中没有前台 Activity 字段 |
| `foreground-null-foreground` | 前台字段存在，且全部明确为 null |
| `foreground-unrecognized-format` | 前台字段存在，但当前解析器不能识别 |
| `foreground-invalid-package` | 解析到的包名不符合现有格式要求 |
| `foreground-outside-grant` | 前台 App 已离开授权范围 |

错误只包含固定原因代码和固定中文说明，不带原始命令输出、包名、Activity 内容或底层异常详情。零退出码中夹带的明确权限、服务或 dump 超时错误也会拒绝，不能凭同时出现的 Activity 文本通过检查。

改动集中在 `electron/device/target.ts`、`electron/automation/debug-step-context.ts` 和 `electron/capture/inspection.ts`。复用原报告的 code/message 字段，没有新增协议、依赖、诊断文件格式或配置。启动采集原来对前台身份失败直接停止的规则改为类型判断，不再依赖旧错误文本。

## 保留的边界

前台未知仍然失败，不拿历史目标补齐，不把 null 当作当前授权身份。六类新错误均不触发新的自动重试。输入前失败不发送操作；输入后失败保留原回执和失败状态，同一 requestId 重复查询不重发。

原来已有的焦点暂空、Helper 动画恢复及其预算不变。取消和外层时间限制仍优先保留原停止原因；并行读取仍等待相关读取结束，且只探测原授权包名。离开授权范围仍停止，不能转成等待另一个 App。
