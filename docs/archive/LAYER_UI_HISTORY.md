## Debug真实控件树

## Debug App 深度控件树改造计划

> 专项实施记录。当前实现和待办以 [项目当前状态](../PROJECT_STATUS.md) 为准。

状态：已实施，进入稳定性维护
日期：2026-09-15

### 目标

只支持可调试的 Android App。当前已接入原生 View 树和 Qt/QML Debug 对象树；Release App 直接提示不支持。

目标 App 不要求修改业务代码。Qt/QML APK 必须自带 QML Debug 插件，程序首次采集时会以 QML Debug 参数重启目标 App。

### 基本规则

| App 状态 | 处理方式 | 页面提示 |
| --- | --- | --- |
| Debug 原生 View | 前台 Activity 的 `dumpsys activity <package>` + DDMS 层级与定点截图 | View Debug |
| Debug Qt/QML | QmlDebugger 真实对象树 + Rectangle/Window 样式重建 | QML Debug |
| Debug 但深度工具不可用 | 停止采集 | 深度检查工具不可用 |
| Release | 停止采集 | 仅支持 Debug App |

不再使用 UIAutomator 的 `VirtualChild` 作为深度产品控件树。fast 自动化模式仍可能返回 VirtualChild；当前深度模式接入原生 View 与 QML，Compose 尚不支持。

### 实施步骤

#### 1. 先做最小技术验证

1. 自动读取当前前台包名。
2. 使用 `run-as <package> id` 判断 App 是否可调试。
3. 已验证官方 `android layout --full` 仍依赖设备端自动化服务，不用于本项目的深度树。
4. 已验证当前 Debug APK 是 Qt/QML App，并成功读取 `QmlDebugger` 真实对象树。

这一阶段必须先证明能消除 `View$VirtualChild`，再进入正式接入。

#### 2. 替换采集源

保留现有 `inspectDevice` 入口，但只允许 `debug-layout` 深度控件树。发现 Release App 或连接失败时返回明确错误，不再回退到 UIAutomator。

截图、设备方向和历史快照继续复用现有逻辑，不再建立第二套界面流程。

#### 3. 统一节点数据

在现有 `UiNode` 上补充可选字段：

- 节点来源：View、Compose、WebView 或 Accessibility；
- 稳定节点 ID、父子关系和真实类名；
- alpha、visibility、elevation / Z、transform；
- padding、margin、background 等深度属性；
- QML 的源文件、行号、对象 ID、几何区域、visible、opacity 和 z；Rectangle/Window 的背景色、圆角、边框与基础线性渐变。

现有树、属性栏和 WebGL 3D 展开继续读取同一个 `UiNode`，避免重写整套前端。

#### 4. 调整界面提示

- 顶部显示“Debug 深度模式”；
- Release App 显示“仅支持 Debug App”；
- 深度连接失败时显示具体原因；
- 删除 VirtualChild 和 Accessibility 兼容提示。

#### 5. 适配 3D 层级

- 使用深度树提供的真实父子关系和 Z / elevation；
- 展开的节点保留自己的独立位图，没有独立位图则显示轮廓；
- 子节点只承载自己的绘制内容，不能复制父层或兄弟层的像素；
- 收起父节点时恢复该分支的合成画面；
- 无独立位图的控件只显示结构轮廓，不使用整屏截图裁切，避免混入其他层内容。

### 验收标准

1. 原生 View Debug App 显示真实类名，不出现成片 VirtualChild。
2. Qt/QML Debug App 显示真实 QML 类名、父子关系和几何属性。
3. Release App 无法开始采集，并获得明确提示。
4. 截图坐标、选中和 3D 高亮与深度控件树一致。
5. 深度工具缺失、连接失败或版本不兼容时不会导致程序崩溃。

### 暂不包含

- 支持或绕过 Release App 的调试限制；
- 对目标进程做 Hook；
- Compose、Flutter 和 WebView 内部树；
- 修改目标 App 的运行数据。

### 推荐实施顺序

先保证当前 Qt/QML Debug App 和原生 View Debug App 稳定，需要 Compose 时再接 AOSP App Inspection 通道。

当前实现和仍未覆盖的边界见 [项目当前状态](../PROJECT_STATUS.md)；历史采集记录见 [采集与图层稳定性改良](INSPECTION_RELIABILITY.md)。

## 3D图层自身画面

原文件：`3D_LAYER_VISUAL_REFACTOR_PLAN.md`。以下保留整理前内容，仅调整标题层级和相对链接。

## 3D 层级视图视觉改造计划

> 历史专项记录。当前实现和待办以 [项目当前状态](../PROJECT_STATUS.md) 为准。

状态：第五轮已完成
日期：2026-09-14

### 1. 问题结论

当前 3D 视图把 hierarchy 中的每个节点都渲染成一张 CSS 3D 平面，并给每张平面铺上同一张设备截图的对应区域。

实际 Android hierarchy 中，很多父节点的 bounds 都是全屏或接近全屏。旋转到侧面后，这些平面会变成重复的“截图纸片”，同时每一层的标签会发生遮挡。用户提供的 macOS 截图中 `Yaw 95° · Pitch 11°` 已经清楚暴露了这个问题。

这不是鼠标旋转或相机计算的问题，核心是 3D 视觉表达方式不合理。

### 2. 改造目标

#### 2.1 核心目标

让 3D 视图解释 hierarchy 的空间关系，而不是复制多张截图：

- 正面视角能清楚看到当前截图和选中节点；
- 侧面视角能看到层级深度，但不会出现重复截图墙；
- 选中节点、树节点、3D layer 和 breadcrumb 保持同步；
- 标签在旋转后仍然可读，不互相堆叠；
- 保留普通左键旋转、右键旋转、键盘方向键和重置操作。

#### 2.2 视觉方向

保留当前浅色工作台和绿色选中态，采用“一个真实表面 + 少量结构轮廓”的表达：

- 选中层：显示主要截图纹理和绿色边界；
- 父级层：显示低透明度轮廓，不重复铺截图；
- 子级层：只有 bounds 明显不同且具有观察价值时才显示纹理，否则只显示轮廓；
- 基准截图：保持低透明度，作为所有层的空间参照；
- 其他层：使用轻量边框区分父级、子级和 VirtualChild。

### 3. 改造范围

#### 3.1 涉及文件

- `src/components/Layer3DPreview.tsx`：调整 layer 的视觉渲染和标签呈现；
- `src/components/ScreenshotPreview.tsx`：保持拖拽、相机状态和视图切换逻辑一致；
- `src/App.css`：调整平面、轮廓、HUD、标签、游标和旋转状态样式；
- `scripts/app-smoke.mjs`：增加 3D 视觉状态和普通左键拖拽验收；
- `tests/layer-layout.test.ts`：只在新增可复用的去重/筛选逻辑时补充测试。

优先在 `Layer3DPreview` 内完成视觉层过滤，不为了这次改造扩大共享数据结构。只有当渲染层需要明确的语义字段时，才扩展 `shared/layer-layout.ts`。

#### 3.2 不在范围内

- 不引入 Three.js、WebGL 或新的 UI 依赖；
- 不伪造 Android 实际 RenderNode、Canvas 或 GPU 层级；
- 不修改 ADB、快照数据格式和现有 hierarchy 解析；
- 不删除左侧树中的节点；
- 不把真实设备 XML 或截图写入仓库。

### 4. 分阶段实施

#### 阶段一：固定视觉基线

使用脱敏 fixture 和当前真实设备各记录三种状态：

1. 3D 重置后的正面视角；
2. 左键拖拽约 45°；
3. 左键拖拽约 90°。

统一使用 100% 缩放、动画完成、无筛选条件，并保留当前三个视觉基线窗口：

- 1264×816；
- 1440×900；
- 1587×1000。

#### 阶段二：减少重复纹理

在渲染前对 layer records 做最小筛选：

- 连续出现且 bounds 完全相同的父子层，视觉上只保留一张纹理；
- 选中层始终保留；
- bounds 有明显变化的子层可以保留纹理；
- 被视觉折叠的节点仍保留在左侧树和 breadcrumb 中；
- 不隐藏真实 hierarchy 数据，只减少重复视觉表面。

第一版优先使用精确 bounds 去重；如果真实设备存在轻微像素差异，再增加小范围容差，不直接使用复杂的几何聚类。

#### 阶段三：区分纹理层和结构层

按节点角色呈现：

| 节点角色 | 默认显示 | 目的 |
| --- | --- | --- |
| 选中节点 | 完整纹理 + 强边框 | 明确当前焦点 |
| 父级节点 | 透明面或线框 | 说明容器关系 |
| 有明显 bounds 变化的子级 | 局部纹理 + 边框 | 说明内容层级 |
| 重复全屏子级 | 线框或弱化 | 避免重复截图 |
| VirtualChild | 虚线轮廓 | 保留能力边界提示 |

平面仍可点击，但被视觉折叠的节点统一通过树和 breadcrumb 选择，避免透明大平面拦截鼠标。

#### 阶段四：整理标签和 HUD

- 只在画布中固定显示当前选中节点的详细标签；
- 父级和子级标签改为悬停或键盘聚焦时显示；
- 详细标签放进 2D HUD，不跟随 3D 平面倾斜；
- breadcrumb 继续显示完整路径；
- 标签增加最大宽度和省略规则，避免长 class 名撑破画布；
- 画布指针在可旋转状态显示 `grab`，拖动时显示 `grabbing`；
- 保持 `prefers-reduced-motion` 下无动画。

#### 阶段五：微调深度和相机

在重复纹理问题解决后再调整参数，避免用视觉参数掩盖结构问题：

- 降低默认层间距，避免层级被拉成过大的扇面；
- 保留 `yaw` 的完整 360°范围；
- 适当限制 `pitch` 的极端角度，避免接近水平面时难以观察；
- 正面重置仍保持 `Yaw 0° · Pitch 0°`；
- 180°附近至少保留结构轮廓和选中状态，不出现整块空白。

### 5. 验收标准

| 场景 | 验收结果 |
| --- | --- |
| 正面视角 | 截图内容清楚，选中层边界明确 |
| 45°旋转 | 能看出父子层间距，没有大面积重复截图 |
| 90°旋转 | 不出现连续的全屏截图切片，标签不重叠 |
| 180°旋转 | 仍能看到结构轮廓和当前选中层，不出现布局崩溃 |
| 普通左键拖拽 | `Yaw/Pitch` 和 3D transform 持续变化 |
| 点击 layer | 选中节点、树节点、属性面板和 breadcrumb 同步 |
| 重置 | 回到正面、100%缩放和默认相机姿态 |
| 小窗口 | 1264×816 下无横向溢出，属性区域仍可用 |
| 无障碍 | 树、按钮、breadcrumb 和键盘方向键仍可操作 |
| 运行稳定性 | 无 renderer error，现有单测全部通过 |

### 7. 实施结果

- `Layer3DPreview` 已按精确 bounds 去重，选中层保留贴图，父级、重复层和 VirtualChild 改为轮廓；有明显尺寸变化的子级保留局部贴图。
- 选中节点信息改为固定 2D HUD，其他节点标签只在悬停或键盘聚焦时显示。
- 轮廓层不再拦截鼠标；父级可通过左侧树和 breadcrumb 选择。
- 默认层间距从 32px 调整为 20px，保留普通左键/右键旋转和安全释放。
- 设备截图底面已放入与层级平面相同的 3D 场景，截图画面会和下方层级同步移动。
- 固定样例、真实设备和三个目标窗口尺寸均已通过验证。

### 8. 完成判定

满足以下条件后再结束改造：

- 3D 视图不再把连续全屏节点显示成重复截图墙；
- 旋转、选中、树同步和 breadcrumb 没有回归；
- 三个目标窗口尺寸没有重叠、裁切或横向溢出；
- 自动化测试和人工截图均通过；
- 改动集中在现有组件和样式中，没有新增依赖。

### 9. Lookin 对照补充

以下内容是对第一版视觉改造的第二轮修复计划，优先级高于前文的第一版实现结果。

#### 9.1 已观察到的界面和操作

本机已打开 Lookin 并观察到实际操作界面：

- 左侧是可展开、可选中的 hierarchy 树；展开操作只改变当前节点的子树范围。
- 中央是 2D / 3D 画布，选中树节点后画布和右侧属性面板同步更新。
- 右侧集中显示 Relation、Frame、Bounds、AutoLayout 等当前节点信息。
- 工具栏提供 2D / 3D、自由旋转、尺寸、测距等操作；自由旋转只作用于中央场景。
- 3D 画面中，当前节点的画面是主要内容，父级更多是退后的结构层，不是重复的全屏截图。

Lookin 的官方实现也不是把每个 View 简单向 Z 轴推开，而是为节点区分包含子视图的 Group 内容和节点自身的 Solo 内容，在展开和收起时切换两种内容：[Lookin 原理说明](https://github.com/hughkli/Lookin/blob/Develop/Docs/Lookin%E5%8E%9F%E7%90%86%E5%8F%8A5%E4%B8%AA%E5%BC%80%E5%8F%91%E9%9A%BE%E7%82%B9.md)。

#### 9.2 当前项目的具体偏差

- 顶部的节点信息卡是 Inspector HUD，不是 Android 的真实 `View`，不应参与层级展开。
- 外层完整手机比例矩形应当只是唯一的截图底图；当前它和全屏容器记录发生了重复显示。
- 根节点、父节点和近似全屏的 `ViewGroup` 被错误地当成截图表面，侧视角下就会变成斜着的薄片。
- 当前多个节点使用同一张设备截图的裁剪区域，不能表达真实的 View 绘制、裁剪和子视图合成关系。
- `UIAutomator` 目前只能提供 hierarchy、bounds 和属性，加上一张整屏截图，无法直接生成 Lookin 那样的每节点 Solo / Group 图片。

#### 9.3 第二轮修复方案

1. 屏幕截图只保留一个底图，并和所有可见结构层放在同一个 3D 场景中，保证左键拖动时整体同步。
2. 根节点、祖先节点、全屏或近似全屏容器只显示边界，不显示截图纹理，也不拦截画布鼠标。
3. 当前选中节点只显示 bounds、选中边框和 HUD；不再复制一张浮动截图。
4. 只展开当前节点的直接子层；`TextView`、`ImageView` 等有内容的叶子节点才允许显示截图裁剪，普通容器默认显示轮廓。
5. 焦点模式只保留最近 4 级父层；选中节点的直接子层与截图底图共用相机变换，折叠节点不继续在画布中铺开更深的后代。
6. 限制极端俯仰角并降低透视强度，避免全屏结构层被压成刀片；这只是防护，不能替代前面的层角色修正。
7. 左侧树保留完整真实 hierarchy，树展开/收起只控制画布展示范围，不删除或修改解析数据。

#### 9.4 验收重点

| 场景 | 预期结果 |
| --- | --- |
| 正面视角 | 只看到一张屏幕底图，当前节点边界清楚 |
| 左键拖动 | 截图底图、选中边界和直接子层一起旋转 |
| 45°视角 | 能看到浅层父子关系，不出现重复全屏截图 |
| 90°视角 | 不出现连续斜片、刀片或悬浮 ImageView |
| 展开节点 | 只增加当前节点的直接子层，父级不重复铺图 |
| 点击结构轮廓 | 不抢占画布拖拽，节点通过左侧树选择 |
| 切换节点 | HUD、边界、树和属性面板同步更新 |

#### 9.5 能力边界

本轮先做基于 hierarchy 和 bounds 的可靠近似，不伪造 Android 的真实绘制顺序。若后续要求完全复刻 Lookin，需要增加 Android 端调试采集能力，为每个节点提供 Solo / Group 或等价的独立截图，并补充裁剪、可见性和实际绘制顺序数据。

#### 9.6 实施结果

- 3D 画布现在只保留一张屏幕底图；根节点、近似全屏容器和深层父级不再重复铺截图。
- 焦点模式只展示最近 4 级父层、当前节点和直接子层，避免深层 hierarchy 变成斜片墙。
- 全屏当前节点只显示边界和 HUD；小尺寸且有内容信号的 ImageView/TextView 会显示自身 bounds 内的截图裁剪，不再放大成悬浮窗口。
- 默认俯仰角限制为 `-65°` 到 `65°`，Yaw 仍可完整环绕。
- 真实设备和 fixture 冒烟均通过；真实设备旋转截图保存在 `.benchmarks/app-smoke/` 对应报告目录的 `layers3d-rotated.png`。

#### 9.7 全屏结构容器修正

真实设备中被选中的 `android.widget.LinearLayout` 覆盖范围为 `1080×2355`，只是包住应用内容的结构容器，不是独立画面。

- 选中节点为近似全屏的结构容器时，直接并入唯一的屏幕底图，不再生成置于最前方的 3D 平面；
- 底图保持选中边界和 HUD，明确当前选择，但不会形成一张悬浮窗口；
- 其他近似全屏结构容器的 Z 位置不会超过屏幕底图，真实的小尺寸内容层仍可按层级拉开；
- 冒烟测试会校验此类选中节点没有额外的 `.layer-plane.selected`。

#### 9.8 清理画布遮挡

- 移除画布内的 breadcrumb、选中信息卡和说明条；当前节点信息由左侧树与下方属性面板提供；
- 所有近似全屏的结构容器都不再绘制为 3D 平面，画布只保留唯一屏幕底图和有意义的小尺寸内容层；
- 这样不会再出现一张透明的 `FrameLayout`/`LinearLayout` 页面遮挡或包住手机画面。

#### 9.9 清理静态截图底板

- 3D 模式下，原截图容器只负责尺寸和手势，不再保留轮廓、阴影、背景或可见图片；
- 可见画面只来自会随相机旋转的 3D 屏幕底图，避免旋转后留下竖直白板；
- 冒烟测试会校验该静态容器没有 outline、shadow 或背景色。

## 3D 全量层级总览改造计划

> 历史专项记录。当前实现和待办以 [项目当前状态](../PROJECT_STATUS.md) 为准。

状态：已实施
更新：2026-09-23

### 1. 目标

截图完成后，直接把整棵可见 UI hierarchy 的所有子节点放进同一个 3D 层栈。用户不需要先点击某个容器才看到它的子节点。

```text
Root（自身画面或参考边界）
 ├─ Child A
 │   └─ A-1
 ├─ Child B
 └─ Child C
     └─ C-1
```

- 所有可见后代一次性沿 Z 轴展开；
- 点击树或画布中的节点，只改变绿色选中态、蓝色悬停态和属性面板；
- 选择容器不会切换到局部子窗口栈，也不会重排其他层；
- 展开时各层只显示自己的画面；收起时合成子树画面，不额外叠加整屏截图。

### 2. 层级顺序

同一父节点按以下顺序放入层栈：

1. `drawing-order`；
2. `index`；
3. XML 出现顺序。

层栈按树结构的绘制顺序遍历（优先使用已采集的原生 `z`，QML 负 Z 子节点在父节点背景之前绘制），但遍历序号不再直接作为展开深度：

- 与已有控件区域重叠时，放到这些控件的前一层；
- 不重叠的兄弟或分支可以共用深度，但仍是独立控件，可单独点击；
- 选择只改高亮，不参与 Z 计算；
- 展开 Z 与 bounds 使用相同的坐标尺度，缩放时 X/Y/Z、相机中心和测距线一起缩放。

这里的 Z 是便于观察的展开距离，不声称是 Android 的实际物理层距。

### 3. 视觉与交互

| 元素 | 表现 |
| --- | --- |
| 有自身样式的控件 | 显示其自身截图区域 |
| 结构容器、无自身样式的控件 | 只显示轮廓 |
| 相同边界的重复空容器 | 更淡的轮廓、较短间距，仍可点击 |
| 选中控件 | 细绿色高亮，不置顶、不使用粗实心框 |
| 悬停控件 | 蓝色高亮，不置顶 |
| Root | 展开显示自身画面或淡边界；收起显示子树合成画面，可点击 |

不再把所有深度压进 24 档。有内容、采集状态未知以及收起的节点保留正常间距；只有明确透明或 `skip-draw`、且边界重复的空节点使用 16% 间距。保留节点、绘制顺序和命中区域，不用隐藏节点制造清爽效果。正常真机截图最多渲染 512 个可见层，并在画布元数据中标记截断状态。

默认从较正的斜视角观察（Yaw 40° / Pitch 12°），展开间距为 96；用户仍可旋转和调整间距。

相机以整个层栈的 X/Y/Z 范围为中心，根据各层实际投影自动取景，每侧预留约 7%。展开/收起、调整间距、改变窗口大小时重新适配；选中、悬停、隐藏和自由旋转不自动改变倍率。手动缩放仍叠加在适配倍率上。

### 历史方案（不再采用）

状态：已替代
日期：2026-09-15

### 问题

UIAutomator 只提供一张完整截图，不会给每个 Android 节点单独输出位图。

因此，父容器在展开时应只作结构边框：它的可见内容已经分别由子节点表示；但当左侧树收起该父容器时，子节点会从 3D 场景移除，父容器必须接回其 bounds 内的截图区域。否则收起后的父层只剩空边框。

### 规则

| 树状态 | 父节点在 3D 中的表现 |
| --- | --- |
| 展开 | 只显示透明边框；即使父节点有文字或虚拟内容，也不保留截图颜色；可见子节点按 Z 序展开 |
| 收起 | 显示父节点 bounds 对应的合成截图；子孙节点不再渲染 |
| 叶子节点 | 保持现有规则：有自身内容时显示局部画面，否则仅边框 |

对于应用暴露的 `VirtualChild` 虚拟子窗口，展开时使用它自己的 bounds 截图区域，连同该区域背景一起移动；接近全屏的虚拟父节点仍只显示边框，避免重复整屏画面。

根节点也遵循同一规则：全部折叠时，根节点应显示完整设备画面，而不是空白边框。

### 实施

1. 在层布局记录中标记“有子节点且当前收起”的节点。
2. WebGL 渲染器把该标记节点作为合成画面层，使用其 bounds 从完整截图裁切纹理。
3. 收起的根节点改为可点击合成层，仍能同步选中树和属性栏。
4. 增加布局单测，验证根节点和嵌套父节点在收起后都被标记为合成层。

### 验收

- 点击“全部折叠”后，右侧显示完整父窗口画面；
- 收起任意中间父节点后，父节点显示该区域画面，子孙层消失；
- 再展开后，父节点回到边框，子节点重新按原 Z 序出现；
- 选中、悬停、点击和属性面板保持同步。

### 实施结果

- 收起的根节点和中间容器都会承接其 bounds 内的合成截图；
- 展开后会自动回到结构边框，避免父子截图重复覆盖；
- 展开的虚拟子窗口会携带其局部背景，不再只剩悬空文字；
- 根节点合成层可点击、可悬停，仍会同步左树与属性栏；
- 已通过布局单测、构建和 1600×1000 的完整 fixture 冒烟测试。

## 空白图层深度排查

> 历史诊断记录。当前实现和待办以 [项目当前状态](../PROJECT_STATUS.md) 为准。

日期：2026-09-22。范围：当前 Android 14 真机上的原生 Debug 视频页面。本文保留初次诊断证据；用户确认后已实施修复，结果见末节。未修改手机 App。

### 结论

本次空白不能等同于背景丢失。已确认两个问题：**不绘制自身的容器被误报为图片匹配冲突；全透明位图没有明确标识，且没有常态轮廓。**

需要纠正此前仅根据界面警告作出的判断：屏幕范围内剩余的 10 个歧义节点，在按对象身份强制读取自身快照后，全部像素的 alpha 都是 0。它们本次没有被遗漏的自身背景。

### 真机证据

- 原桌面快照显示 820 个节点。另行完整采集得到 1153 个节点，约 41.9 秒；动态页面各次节点数会变化，以下统计不混用批次。
- 该次采集得到 195 张独立图片，其中 95 张对应屏幕范围内节点；逐像素检查有 26 张全透明、69 张有非透明像素。
- 屏幕范围内没有图片的真实节点：108 个标记为跳过自身绘制，另有 10 个歧义节点，同样标记为跳过自身绘制。额外的 Activity 合成根不是实际 View，不纳入漏图计数。
- 对这 10 个歧义节点进行独立快照实测：8 个 FrameLayout、2 个 TKYogaLayout，全都返回透明图片，耗时约 5.9 秒，无失败。
- 两张 TextureView 图片都读取成功，尺寸分别为 1247×2218、1251×2218，像素不透明。
- 本次总览有 213 个候选层，未触及 512 层上限；没有采集失败或补采上限警告。未发现“已标记需要自身绘制的屏内节点却完全没得到图片”的情况。

### 根因 1：位图匹配候选集合过大

位置：`electron/adb.ts` 的 `attachViewLayerImages`。

Android 批量图层接口会跳过 `PFLAG_SKIP_DRAW` 节点。我们的候选集合却加入了这些节点，导致没有自身图片的父容器和真正绘制的子控件争抢同一条匿名图片记录。

实际例子：9 个同名、同位置、同尺寸的 FrameLayout 中，8 个跳过自身绘制，只有 1 个实际绘制；系统也只返回了 1 张该矩形的图片。原逻辑把 9 个节点全部判为歧义。后续按对象身份补采恢复了真正绘制的那个节点，但 8 个空容器仍留着歧义警告。

独立保存一批原始数据后进行离线对照：排除跳过自身绘制的普通节点参与匿名图片匹配，匹配数从 125 增至 128，歧义节点从 15 降至 0。恢复的 3 张均对应真正绘制的节点；其中 1 个在屏幕之外。这是诊断实验，不是已发布修复。

此外，顶部警告统计整个树，没有区分屏内与屏外；完整采集的 13 个剩余歧义节点中有 3 个在屏外，用户容易把它们都理解成当前可见画面的缺失。

### 根因 2：透明位图被当作普通有内容图层

位置：`src/components/Layer3DPreview.tsx` 的 `hasOwnVisualStyle` 和 `scenePlanes`；`src/components/NodePropertiesPanel.tsx` 的状态映射。

原逻辑只要存在图片，就选择贴图渲染；全透明 PNG 也进入这条路径，未额外绘制普通轮廓。属性栏只提示“已采集独立画面（可能透明）”，并没有报告是否实际验证为透明。所以有些节点看起来直接消失，无法与漏采区分。

26 张透明图片包含布局包装、点击区域、占位层等。这里的结论是“采集时图片确实透明”，不代表这些控件在所有运行状态下都不会绘制。

### 建议修复顺序

1. 普通跳过自身绘制的节点不参与匿名批量图片匹配，但保留树和几何信息；SurfaceView/TextureView 仍走已接入的独立缓冲通道。未知标记、真正同名同矩形歧义仍保守拒绝，不按顺序猜归属。
2. 将已验证全透明、系统跳过绘制、真实匹配失败、读取失败区分展示。透明层保留细轮廓；不添加虚构背景，也不复制父层或整屏画面。
3. 警告区分屏内/屏外，加入“无绘制父容器与有背景子节点同矩形”的回归用例；重跑展开、折叠与视频图层检查。

- 仍修正了一个真实的漏采条件：`PFLAG_SKIP_DRAW` 只跳过普通绘制，快照仍会调用 `dispatchDraw` 并绘制 overlay。旧代码直接跳过这类节点，会漏掉某些自绘容器的装饰。现在检查真实继承链中的 `dispatchDraw` 覆盖及 overlay，仅跳过没有这些绘制来源的结构容器。依据：[AOSP View.createSnapshot](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/View.java)、[ViewGroup.createSnapshot](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/ViewGroup.java)。

- 读取失败的自绘容器不再因 `skip-draw` 标记而按空容器压缩层距。对象身份匹配、排除子节点、视频保护检查及 64 个 / 400 万像素 / 15 秒补采上限不变。
- 104 项单测、生产构建、3 档缩放各 45 组 WebGL 检查通过；回归覆盖继承的自绘方法、类型缓存、overlay、失败节点层距。真实图片逐层加载与像素抽样未发现整层漏显；极低透明度边缘的采样差异不视为逐像素无损证明。

## 选中 ImageView 3D 浮层视觉修复计划

> 历史专项记录。当前实现和待办以 [项目当前状态](../PROJECT_STATUS.md) 为准。

状态：已完成
日期：2026-09-14

### 1. 问题描述

在 3D 层级视图中选中 `ImageView` 后，它会像一张独立图片一样浮在最上方。旋转到侧面时，这个小图片和截图底面、其他层级分离，视觉上像设备中真的存在一块悬浮面板。

### 2. 原因判断

- `ImageView` 节点本身是真实设备 hierarchy 中的节点，当前设备中的 bounds 为 `135×135px`。
- 3D 视图把每个节点都映射成 CSS 3D 平面；选中节点使用截图纹理和高优先级 `z-index`，因此被视觉上突出。
- `UIAutomator` 只提供 bounds、树深度和属性，不提供真实 RenderNode、Canvas 或 GPU Z 轴。树层级不能直接当作真实绘制顺序。
- 所以问题主要是可视化表达方式，不是设备多出了一层 ImageView。

### 3. 修复目标

- 选中 `ImageView` 仍然保留准确的 bounds、选中状态和节点信息。
- 选中节点不再显示成单独的截图贴图，不再产生“浮在最顶层”的错觉。
- 使用绿色边框、轻微光晕和 HUD 表示当前选中节点。
- 截图底面、结构轮廓和普通可观察子层继续保持同步旋转。
- 左侧树、3D 层、breadcrumb 和属性面板继续同步。

### 4. 最小改动方案

#### 4.1 调整选中层渲染

修改 `src/components/Layer3DPreview.tsx`：

1. 选中节点继续保留为可交互的 layer plane，保证点击和键盘操作不回归。
2. 选中节点不再铺设截图纹理，改为透明面或仅保留结构边界。
3. 选中节点的文字信息继续放在 2D HUD 中，不跟随平面倾斜。
4. 保留普通子层的局部纹理，让有明显 bounds 变化的层仍然有空间参考。

#### 4.2 调整选中状态样式

修改 `src/App.css`：

1. 取消选中 `ImageView` 的截图背景和大面积绿色填充。
2. 保留绿色边框、细光晕和可读的选中标记。
3. 让选中层的视觉重点落在 bounds，而不是图片内容。
4. 保持 `prefers-reduced-motion`、键盘聚焦和浅色主题样式。

#### 4.3 增加验收标记

修改 `scripts/app-smoke.mjs`：

- 检查选中层仍存在且跟随树选择；
- 检查选中层的 `data-layer-texture` 为 `false`；
- 检查截图底面仍在同一个移动场景中；
- 保持左键拖拽、拖出窗口释放、键盘旋转和重置检查。

### 5. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 正面视角 | 选中 ImageView 只显示 bounds 高亮，不像独立图片浮起 |
| 45°旋转 | 选中框与截图底面、层级轮廓保持同一相机变换 |
| 90°旋转 | 不出现单独的 ImageView 贴图或大面积悬浮图片 |
| 点击选中层 | 树、breadcrumb、HUD 和属性面板同步更新 |
| 切换其他节点 | 旧选中状态清理，新节点只显示边界高亮 |
| 重置视角 | 回到 `Yaw 0° · Pitch 0°`，层级关系仍可读 |
| 小窗口 | 1264×816 下无横向溢出，HUD 不遮挡主要画面 |

### 6. 验证方式

```bash
bun run build
bun test
node --experimental-websocket scripts/app-smoke.mjs --fixture --viewport=1264x816 --drag-outside
node --experimental-websocket scripts/app-smoke.mjs --require-device --viewport=1264x816 --drag-outside
bun run visual:baseline
```

人工检查：

1. 选中真实设备中的 `ImageView`；
2. 重置后分别拖动到约 45°、90°和 180°；
3. 确认 ImageView 只作为边界标记存在，截图和其他结构层同步移动；
4. 检查树选择、breadcrumb 和属性面板没有回归。

### 7. 实施结果

- 选中层不再铺设截图纹理，仅保留透明 bounds 高亮和 HUD。
- 截图底面继续与层级平面共用同一 3D 场景，并跟随拖拽同步旋转。
- smoke 增加了 `data-layer-texture=false` 验收，避免选中层再次变成悬浮贴图。
- 构建、56 个单测、fixture、真实设备和人工拖拽检查均通过。
- 三个固定窗口尺寸的视觉基线均通过，确认没有出现独立的 ImageView 图片层。

### 8. 不在本次范围内

- 不推断真实 Android RenderNode 或 GPU 绘制顺序；
- 不修改 UI hierarchy 解析、ADB 连接和截图数据格式；
- 不引入 Three.js、WebGL 或新的渲染依赖；
- 不删除左侧树中的真实节点。

### 9. 完成判定

当选中的 `ImageView` 不再以截图贴图形式浮在最上层，同时保留节点定位、选中同步和 3D 旋转能力，并通过构建、单测、模拟数据和真实设备验证后，本计划完成。
