# D17：设备采集协作式退出

更新：2026-10-18。状态：可选入口已实现，相关测试、构建、ART 故障夹具和自有 App 真机只读验证通过。默认采集路径不启用，手机已恢复原 Helper。

## 做了什么

桌面现在可以给一次读取传入剩余预算；取消或预算到期时，向设备发送该请求的取消消息。设备在安全检查点停止旧采集，由原工作线程释放锁。

这解决的是“桌面已经放弃，设备仍继续采集”的生命周期问题。已经进入的 Binder 调用、截图或编码不能保证立即中断，必须等调用返回后再检查退出状态。本轮没有新的完整业务提速结论。

## 实现范围

- 新增 `InspectorReadControl.java`：请求身份、截止时间、取消状态和有界登记表。
- 保留原 `/inspector/snapshot` 和原能力响应。新增受原令牌认证保护的 `/inspector/read-capabilities`、`/inspector/read`、`/inspector/cancel-read`。
- 请求绑定会话、请求 UUID、服务实例、包名和原令牌。取消先于读取到达时，保留取消记录；重复取消幂等，错误身份不能修改已有请求。
- 使用设备单调时钟计算截止时间，并扣除设备端已发生的排队和请求处理时间。桌面先扣除连接、能力检查消耗，再发送剩余预算；不依赖两端时钟同步。
- 节点访问之间、截图后、PNG 前后、Base64 后、序列化前后和登记输入证据前检查状态。取消不会强制解锁，不会重发输入。
- 受控快照先保存待提交身份，完整序列化后再原子决定“完成”或“取消”。被新采集替代的旧结果不能覆盖新输入证据；失败或已取消的结果不登记可输入身份。
- 桌面仍执行原来的树、窗口、显示器、PNG 解码及服务身份检查，另核对受控响应的请求 UUID。

取消消息最多发送一次，清理等待上限为 250ms，然后按原规则关闭自有转发。该时间只用于清理，不延长读取或动作预算。消息发送失败不表示设备已退出；设备还依靠原截止时间在下一检查点停止。

登记表最多 32 条，结束记录在截止时间后保留 60 秒；仍在运行的记录不被清除。容量不足直接拒绝，不挤掉未完成或尚需防止重放的记录。这一限制尚未经过完整业务吞吐验证，默认接入前必须核对。

## 如何启用与兼容

现有 `session.read(adb, package, frame, signal, afterResponse)` 保持原入口。仅明确传入第六个参数 `remainingBudgetMs` 时，才调用受控入口；调用方必须使用自身当前剩余预算，不能填写一个新预算来延长步骤。

旧 Helper 缺少受控能力端点时，只有 HTTP 404 才回到原 GET 读取，仍受同一剩余预算约束。畸形能力响应、服务变化、身份不符或设备读取失败不会触发隐式换源或重复采集。旧桌面也能继续使用新 Helper 的原入口。

当前业务执行器尚未自动传入此参数，所以日常界面仍走原路径。这次没有新增第二套执行框架，也没有扩大授权、恢复次数或步骤期限。

## 真机过程与范围

设备 `JNHA45FQBQEIRGEQ`，目标为已经安装的自有 `com.androiduiinspector.sdkfree`。启动其主测试页后，没有点击、滚动、返回或修改设置。原 APK 已备份，新 Helper 同包覆盖安装并保留数据；本次调试仅授权该测试 App。

首次试跑在第一条读取后停止：回测程序错误使用了旧的“整窗可操作”检查，没有执行后续取消。恢复原 Helper 后做一次有界基线，实际结果为：完整观察通过、安全上下文通过、整窗可操作不通过。窗口清单保留了覆盖测试页部分区域的真实系统悬浮窗。

首次程序在保存返回之前执行了该检查，所以那次只有失败与停止记录，无法还原当时窗口的精确组合。第二轮已改为先保存原始返回再验收，原版基线与第二轮证据均完整保留。

随后在第二版协议中明确只读验收边界：保留所有产品解析、树、PNG、显示器和身份校验；要求完整观察及安全上下文，额外记录整窗可操作结果。没有隐藏悬浮窗，也没有将其判为可点击。原失败、原版基线和修正后的协议分别保存。

第二轮结果如下，单位为秒；时间包含对应 API 调用及必要连接检查，不是单独的设备执行耗时。

取消在受控 POST 发出 50ms 后触发，取消 HTTP 回执约 24.6ms。之后按协议静置 500ms，再发起显式新读，没有自动重试。**0.146 秒不是精确锁释放延迟**：回执表示取消状态已经登记，下一次新读成功说明锁随后可用；本轮没有设备释放锁瞬间的端到端跟踪。

四份完整读取的整窗可操作结果均为 false，遮挡事实保留。这轮只读验证不证明可以点击任何被遮挡区域，也不代表真实收藏流程已使用新入口。
