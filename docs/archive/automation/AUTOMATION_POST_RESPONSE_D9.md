## 改动

原顺序：收完响应 → JSON/树解析 → PNG 完整解码校验 → 会话检查 → 目标与屏幕后验检查。

新顺序：收完响应后启动目标与屏幕后验检查，同时解析并校验本次数据。两路都结束后，仍完成会话、服务实例、采集时序、端口归属和配对检查，再决定是否接受观察。主要可重叠的是异步 PNG 解码；同步 JSON/树解析仍会占用主线程。

后验检查只能在 HTTP 成功、响应体完整收到、大小限制通过且流清理结束后启动，不能由响应头触发。截图、分辨率、无损编码、检查次数与原始期限不变。

失败分支也等待并行任务结束，随后才释放连接。采集失败优先于后验失败；正式观察器暂存后验错误，让原有会话检查先决定结果，再报告后验错误。取消或超时不能发布观察，也不补发输入。旧的直接读取调用没有传入回调时保持顺序执行。

入口：`electron/capture/helper-observation.ts`、`electron/capture/helper-session.ts`、`electron/automation/device-actions.ts`。

## 隔离回放

固定使用 D7 个人页、播放页的树和 PNG，各做 AB/BA 两种顺序，每种顺序一次预热、六次正式配对，共 24 对正式样本。基线和候选使用同一生产解析器，候选在注入响应的读取器返回 EOF 后启动真实设备的只读目标/屏幕检查。两路始终汇合。

归档只保存了选中窗口 XML，缺少系统窗口原始 XML。首次直接重建多窗口响应被严格校验拒绝，失败日志保留。正式回放明确改用“选中窗口树＋同一窗口清单”的重建夹具；它不是原始完整 HTTP 响应，也不能授权产品输入。每次输出的树、XML、PNG、观察元数据和几何摘要均与基线一致，PNG 与冻结输入摘要一致。
