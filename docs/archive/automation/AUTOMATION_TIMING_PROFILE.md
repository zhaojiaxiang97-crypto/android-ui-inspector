# 自动操作采集耗时剖析（阶段 D1）

更新：2026-10-17。阶段 D1 已实现并完成新版完整流程验证：111 项测试、类型检查及完整构建通过。单轮业务与证据通过，墙钟 65.613 秒、6 次确认输入、0 次未知输入。本阶段补齐计时和可重复汇总；不改变采集、输入、恢复或证据校验策略，不将诊断改动宣称为提速。

## 已有数据与本次补齐

手机 Helper 已在观察协议中提供树遍历、截图、窗口后验、PNG 编码和 Base64 编码时间。原报告把这些数据留在快照里，主机耗时汇总没有使用它们；被裁剪的中间观察和未成功采集的尝试也没有对应快照。仅看最终保留画面会遗漏恢复成本。

本次复用已有手机协议，无需更新 Helper：

- 主机请求的响应头、正文和 JSON 处理增加固定端点标签：能力检查或实际采集。旧报告缺标签时记为未标注。
- 在 `helper_tree` 计时中保留本次响应的合法手机计时和原始完整性布尔标记；即使随后控件树校验失败，合法计时仍保留。格式不合法或字段缺失时不补零，也不修复原错误。
- 手机计时只保留有限数值，不保存页面、选择器、包名、URL、令牌或异常原文；不把手机单调时间放到主机时间轴上。
- 新增离线汇总脚本，使用现有报告加载器核对冻结归档。步骤重复导出只计一次，旧快照按服务和采集编号去重，冲突数据停止汇总。

协议、时序与计时字段仍严格校验。两个设备计时字段成对出现且只允许在 `helper_tree`；端点标签只允许在四个请求相关阶段。报告可读取旧版缺字段数据，计时对象的输入和输出均复制，避免外部改写污染后续报告。

## 如何汇总

在项目根目录执行，输入必须是回测目录的冻结 `samples.jsonl`，输出必须是新文件：

```sh
bun scripts/helper-timing-profile.ts \
  --samples /absolute/regression-run/samples.jsonl \
  --out /absolute/new-timing-profile.json
```

脚本只读取所选回测目录内已记录的归档，不访问正在变化的原始报告，也不会连接或操作手机。输入有大小和归档数量限制，输出默认仅本机用户可读，已有文件不覆盖。

汇总按现有步骤与父观察关系分为普通读取、自动重读、独立只读恢复，不靠手机与电脑时钟的近似匹配。设备的“声明完整”只是一项诊断，不能代替输入成功、PNG 校验或业务断言。

有两组不同覆盖范围的数据：

1. **每次读取尝试**：新版按父观察准确关联，包含有效设备计时的成功或失败尝试；显示没有设备计时的尝试数量。
2. **保留快照**：兼容旧报告的去重快照子集。不能与上一组相加，也不能视作全流程所有读取。

主机请求、响应头及设备阶段之间有包含关系，不能累计成总耗时。设备未归属时间仅是观察总时长中未拆分的区间，不能当成网络排队或 JSON 响应序列化耗时。

旧报告的 77 次主机观察都没有逐尝试设备计时字段，但 57 个唯一保留快照含完整设备计时。不是 77 次手机采集都没有计时，也不是其余读取耗时为零。

## 新版完整流程验证

本机私有运行目录为 `.benchmarks/stage-c/timing-profile-pilot/`，其中 `timing-profile.json` 由新离线脚本直接生成。手机 Helper 未更新，桌面按原配置重启。完整流程 1/1 通过，产品耗时 60.031 秒、墙钟 65.613 秒，6 次唯一确认输入、0 次未知输入；恢复没有新增输入。10 个唯一步骤的计时无丢弃，归档未报告缺树、缺图、无效附件或录制错误。

| 观察类别 | 主机尝试 | 有合法设备计时 | 无设备计时 | 观察合计 |
| --- | ---: | ---: | ---: | ---: |
| 普通读取 | 21 | 20 | 1 | 41.321 秒 |
| 自动重读 | 3 | 1 | 2 | 2.931 秒 |
| 独立只读恢复 | 2 | 2 | 0 | 4.629 秒 |
| 合计 | 26 | 23 | 3 | 48.882 秒 |

23 次设备计时中有 22 次最终观察成功、1 次观察失败且 Helper 声明不完整。失败仍是失败，但它的手机处理时间没有再被丢掉。旧快照子集仅有 19 次、20.290 秒，因此不能继续用保留快照代替完整尝试统计。

独立核验确认另外 3 次都在 `target_before` 阶段停止，没有发出 Helper 采集请求，因此没有设备计时是准确结果。实际发出的 23 次采集请求全部具有合法、完整的设备阶段计时，均按原父观察关联，没有用近似时间匹配。

| 23 次合法设备计时的阶段 | 合计 |
| --- | ---: |
| 树遍历 | 14.952 秒 |
| 截图 | 1.318 秒 |
| 窗口后验 | 0.853 秒 |
| PNG 编码 | 6.239 秒 |
| Base64 编码 | 0.470 秒 |
| 观察内部尚未拆分区间 | 1.165 秒 |
| 设备观察总计 | 24.997 秒 |

端点标签完整覆盖：3 次能力检查的响应头等待合计 **0.043 秒**，23 次实际采集的响应头等待合计 **32.316 秒**。与这 23 次对应设备观察总时长相比，还有约 **7.319 秒**位于既有设备观察计时之外。差额可能包含请求到达、服务调度、返回前序列化与传输等部分，当前不能把它命名为纯网络或 JSON 开销。

主机来源检查区间合计 12.563 秒，其中 11.197 秒位于观察内，1.366 秒位于其他操作边界；它们与观察总时长重叠。另有观察外的 Helper 请求 4.152 秒和保存证据 0.555 秒，分别单列，不挤入采集端点统计。树读取与 PNG 编码仍是最大两项已知设备成本，保存报告不是本轮主要瓶颈。

实现经独立审查。整合测试覆盖旧数据兼容、固定字段、合法失败响应计时保留、无效或缺失计时、取消、嵌套对象隔离、选中导出重读、重复步骤与采集冲突、路径边界和隐私。最终 111 项 / 11 文件通过，类型检查、完整构建及差异检查通过，历史归档未改写。

新单轮的 **8 份冻结归档、42 个附件**经独立摘要、长度和实际加载检查全部有效，末端、末卡与同请求恢复链通过。另一份独立统计逐项核对脚本的次数、总量、均值、最值、分组及覆盖范围，结果一致。测试后已停止调试授权，新版软件保持运行，原分支、暂存区和已有修改保留，未提交或推送。

## 后续边界

本轮之后已完成 [D2 内部拆解](AUTOMATION_TIMING_DETAIL.md)：通过独立响应头补齐服务器调度、序列化、UTF-8 及树子阶段，23 次请求全部覆盖，新完整流程和 42 个附件核验通过。本轮历史数字保留不改；后续优先级见该文及下一步计划。

当前读取锁使用 `tryLock`，立即成功或拒绝，没有锁等待队列；不能把未解释时间直接称为锁排队或 Binder 耗时。

D2 已按此边界单独更新手机端并验证兼容，响应仍只序列化一次，计时不引入额外采集。来源检查的批量查询也需保持每项退出状态及动作前后重新核对，不缓存焦点。

性能优化仍按 [阶段 D 计划](../../AUTOMATION_NEXT_STEPS.md) 做同条件前后各至少 10 轮成功流程，并分别记录首轮、后续和失败。当前数字是诊断基线，20% 降时仍为待验证目标。
