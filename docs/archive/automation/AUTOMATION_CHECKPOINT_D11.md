# D11：去掉检查点的重复采集

更新：2026-10-17。代码已整合；整合后 177 项 / 15 文件相关测试、类型检查和完整构建通过。真机只读对照和同一会话三轮完整流程均通过。检查点局部产品耗时中位数减少 34.4%，本轮没有重新做完整业务 A/B，不能据此宣布整段提速达到 20%。

## 实现

原检查点先单独 `capture`，再 `wait` 取得两个新帧，共采集三次。新版允许 `wait` 显式指定后端，直接在同一验证步骤内取得首帧，再沿用现有双帧循环读取第二帧，共采集两次。

没有复用上一条命令的旧截图。partial 的两帧仍必须来自本步骤，两个快照 ID 不同；服务、窗口、显示器、完整性、唯一目标和可见区域检查保留。原期限覆盖首次采集和后续等待，取消不会延长期限或触发输入。路径短暂变化仍只允许 D7 已有的一次新双帧重建。

CLI 示例：

```sh
android-ui wait --session '<已有授权会话>' \
  --backend accessibility-helper \
  --resource-id 'com.example:id/result' --state visible
```

MCP 的 `wait_for_ui` 同样支持可选 `backend`。省略时保持原来的来源推断，没有新增默认后端；显式切换来源时先撤销旧快照，新来源失败也不能使用旧 ID。

回测脚本在每个条件中传入计划后端，不再单独采集。完成条件后立即冻结归档，再进行后续读取或输入。多个条件各自取得本步骤新双帧，不拿上一条件的结果凑数。

改动入口为 `shared/debug-protocol.ts`、`electron/automation/debug-step-executor.ts`、`electron/automation/cli.ts`、`electron/automation/mcp-server.ts` 和 `scripts/automation-ui-regression.ts`。没有新增执行框架、依赖、Helper 版本或手机设置。
