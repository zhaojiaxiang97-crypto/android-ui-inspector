# D16：取消后设备仍忙的复现

更新：2026-10-18。状态：故障夹具、桌面回归和手机 ART 复核完成；本轮仅增加测试，没有改变生产取消协议。

## 结论

问题发生在设备采集的生命周期。桌面取消 HTTP 请求、删除自己创建的转发，会停止桌面等待，但不会自动中断设备正在执行的树遍历或 PNG 编码。

当前设备快照方法没有接收取消标记或读取截止时间。`READS` 锁在整个快照方法返回时才释放，所以旧请求还在树读取或编码时，新请求会立即失败。本轮复现了与 D14 相同的“无截图、不完整、诊断原因为空”的忙碌响应；这支持之前的解释，但不能倒推出 D14 每次超时都发生在同一阶段。

JSON 序列化与 HTTP 写回发生在解锁之后，必须与前面的占锁问题分开处理。阻塞这两个阶段时，另一个快照可以正常读取。

## 怎么验证的

新增测试直接提取并执行生产快照、序列化和生成的 HTTP 快照路由、发送方法。使用真实本地 TCP 连接，客户端关闭连接后，再发出新的只读请求。

Android 控件、窗口、截图由固定替身提供，在四个位置使用有界闩锁暂停。请求编号 1、2、3 是测试夹具的本地标签，当前生产快照接口还没有本轮新增的取消请求编号。

| 取消时旧请求的位置 | 关闭连接后旧线程 | 读取锁 | 第二次请求 | 放行旧请求后的显式新读 |
| --- | --- | --- | --- | --- |
| 获取子节点期间 | 仍在执行 | 仍持有 | 拒绝，无完整证据 | 成功 |
| PNG 编码入口 | 仍在执行 | 仍持有 | 拒绝，无完整证据 | 成功 |
| JSON 序列化入口 | 仍在执行 | 已释放 | 成功 | 成功 |
| HTTP 首次写回入口 | 仍在执行 | 已释放 | 成功 | 成功 |

夹具同时检查：无锁泄漏、零输入动作、忙碌响应不能提供完整快照；JSON/写回阶段的旧响应结束后，不会覆盖新读取在设备侧保存的输入证据身份。

日志保存阻塞、客户端关闭、快照返回和工作线程结束的单调时钟时间。`snapshotReturnedAfterUnlockNs` 在快照返回后记录，是解锁时间的上界，不冒充精确锁释放时刻。阻塞长度由夹具控制，不用于计算性能收益。

## 桌面端的取消边界

另补两条真实桌面会话链路回归：

1. 响应头尚未返回时取消，旧服务稍后尝试返回完整树和截图。
2. 完整响应体已读完、后验检查尚未结束时取消。

两种情况下旧读取均拒绝返回结果，转发按原规则清理；随后只有显式发起的新读取获得可操作快照。每条测试只有两次快照请求，没有取消后自动补读，也没有输入请求。使用现有适配器和 PNG 校验，没有因测试关闭身份、几何或截图验证。

这两条回归与 Java 锁夹具分开执行，不声称已经把整套 Android 服务和桌面程序连成端到端故障测试。

## 手机运行环境复核

将同一组最终 Java 夹具编译为 DEX，通过 Android 14 的 ART 运行四个场景，结果与桌面 JVM 一致。手机实际执行了 TCP 断开、线程同步和锁检查。

这里仍使用控件、截图替身；**不是已安装 Helper 的真实 Accessibility/Binder 读取，也不是自有 App 的完整 UI 回测**。因此它证明运行环境中的取消与占锁关系，不证明系统调用可以被立即打断，也不能据此给出真实设备的释放延迟。

没有更新 Helper、安装 APK、修改设置、切换 App 或发送手机输入。只推送了自有夹具 JAR，四项结束后已删除对应临时文件。没有读取或记录设备配对令牌。

## 下一步 D17：设备采集协作式退出

下一步应在设备读取上下文中传递有界截止时间与取消状态，先做独立候选。要求如下：

1. 读请求有明确身份，并绑定原令牌、服务实例和原读取预算；不能用取消一个旧请求的消息误停新请求。
2. 在节点访问之间、截图后、PNG/序列化之前、完成证据登记之前检查退出状态。已经进入的系统调用未必可中断；只能在它返回后退出，不能承诺立即停止。
3. 桌面取消后停止发布证据；设备已取消的读取也不应重新登记可输入的快照。取消应幂等，完成与取消竞争时只能有一个确定的结束状态。
4. 锁由原工作线程在 `finally` 中释放，仍忙时拒绝新读。不能强制解锁，也不能在设备请求尚存活时并发复用可变采集状态。
5. 先用本轮四个阻塞点验证候选，再在自有 Debug App 与真实 Helper 上做小规模验证。旧版兼容、取消身份错误、取消过晚、预算到期和系统调用迟返都必须覆盖。

本轮还没有实现这套协议，也没有验证真实 Binder 读取的退出行为。D17 通过上述验证前，不整合到默认采集路径，不增加恢复次数或放宽期限。
