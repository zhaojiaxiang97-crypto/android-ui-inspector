## 修正内容

### 被底栏挡住的页脚

以前只要结束标记被系统栏遮挡，滚动就立即停止；同 App 底栏不属于独立窗口，标记只露一部分时又可能被误认为已经到达。

现在结束标记必须完整位于有效视口内，排除已识别的 App 导航栏，并通过原窗口检查。实时执行和报告重读使用同一判断，不能靠报告的快捷路径跳过。

需要继续露出底部标记时，在 `scroll_until.until` 明确设置：

```json
{
  "selector": {
    "resourceId": "com.example:id/end_marker",
    "className": "android.widget.TextView"
  },
  "kind": "end_marker",
  "reveal": "scroll"
}
```

首版仅支持 `accessibility-helper` 和 `down`。容器和目标均需精确资源 ID、类型；唯一目标完整属于原容器及祖先裁剪范围，只因已知底栏挡住时，才可继续原方向查找。原次数、时间、进展与取消限制不变。最终仍要求两份新观察完整确认。未知窗口、隐藏或重复目标、其他裁剪、加载冲突会停止；“没变化”不算到底。

### 原操作失败后的只读恢复

以前把“操作后采集没有产生观察”和“引用的图片/树文件丢失”都记成缺附件。即使后来同请求只读恢复保留了完整双帧，也无法继续。

现在分别记录两类缺口。仅对明确已发送、因操作后采集失败而没有 after 的 Helper 复合单步，允许用完整的同请求 `partial` 双帧恢复链继续。必须保留原输入前附件和原失败，核对请求、输入、预期条件、失败指纹、手机采集编号及单调时钟；首帧不得早于输入完成。正常导航换窗口仍允许，恢复双帧之间必须来源稳定。

原失败归档仍为失败，不重写历史；实际缺树、缺图、来源变化或未知输入仍停止。`absentObservations` 是各份归档的未产出观察槽位累计，同一缺口可能重复出现，不是丢失附件的数量。
